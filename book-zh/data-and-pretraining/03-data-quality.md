# 3. 数据质量

质量过滤和去重是整条流水线里杠杆最大的两步。本节讲它们各自怎么工作、什么时候用哪个，以及那些悄悄伤害你的失败模式。

## 标签从哪里来

预训练没有逐样本的标准答案，但每个质量过滤器背后仍然有一个标签在驱动：保留/丢弃的决定、分类器模仿的参考语料，或者评审模型打出的分数。知道这个标签的来源，就知道它给语料烙下了什么偏差。

| 来源 | 能给你什么 | 偏差 / 成本 |
| --- | --- | --- |
| 隐式的生产信号（用户引用哪些来源、消融掉某个数据切片后下游 benchmark 的变化） | 量大，而且把保留/丢弃的决定落在真实的下游任务表现上，而不是靠直觉 | 偏向当前流水线和用户已经能看到的东西；只能衡量评测已经覆盖的能力 |
| 人工标注 / 专家标签（Wikipedia 和图书这类精选参考语料、人工打分的教育质量样本） | 质量高；给学习式分类器和 perplexity 参考模型提供锚点 | 量少、贵；标注者对"质量"看法不一，参考集的文体会变成语料的文体 |
| 合成 / 模型生成（LLM 打的质量分、指令格式的正样本、数据增强） | 能给数万亿 token 打标签，再交给快速分类器规模化应用 | 会把打分模型的偏差传下去，还有评审循环论证的风险，所以必须过同样的启发式、去重和去污染闸门 |

压倒一切的规则：评测集绝不能泄漏进训练语料，也不能泄漏进过滤器训练用的参考集，否则 benchmark 数字衡量的是记忆而不是能力。这就是为什么去污染要在第一个训练 token 之前跑，而不是之后。

## 启发式质量过滤

启发式过滤器是一组便宜、可解释、逐文档应用的规则。经典来源是 Gopher 的规则集和 C4 的过滤配方：

- **长度上下限。** 词数低于下限的文档多半被截断或本来就是空的；特别长的可能是数据倾倒。
- **平均词长。** 平均词长很短说明是符号垃圾或编码问题；很长说明 token 粘连在一起了。
- **符号与词的比例。** 特殊字符相对单词的比例偏高，说明是页面模板、标记语言残留，或者混进散文语料的代码。
- **以标点结尾的行占比。** 散文通常以标点结尾；项目符号列表和导航栏不会。
- **文档内重复行或重复段落的占比。** 重复的块说明是模板或生成的填充内容。
- **停用词是否出现。** 目标语言里一个常见停用词都没有的文档，可能是乱码或者语言识别错了。
- **C4 规则。** 丢掉没有句末标点的页面，丢掉"lorem ipsum"，丢掉含花括号的页面（把代码从散文语料里剔掉）。

FineWeb 消融研究的关键发现：正确的启发式规则集很小。五十多条看起来合理的候选规则里，只有寥寥几条在消融时真的影响下游 benchmark 分数。把每条看起来合理的规则都堆上去，收益不会叠加，反而可能删掉有效文本。选规则要靠在下游评测上做消融，不靠直觉。

## 学习式质量分类器

学习式分类器根据一篇文档和已知优质参考语料的相似程度来打分。

**基于 perplexity（CCNet 风格）。** 对每种目标语言，在可信的参考语料（Wikipedia 或图书）上训练一个小语言模型，然后保留在这个模型下 perplexity 低的网页文档（perplexity 衡量模型对文本有多"意外"，低就表示看起来眼熟）。perplexity 低意味着文本像参考语料，这是"格式规范、信息量足"的一个便宜代理指标。CCNet 按语言分别做这件事，多语言质量过滤才因此变得可行。

**FineWeb-Edu 风格。** 先用一个强 LLM 按教育质量（0 到 5 分）给一批文档样本打标签，再用这些标签训练一个快速分类器（DistilBERT 量级的模型），然后规模化应用到整个语料。只保留高分文档（FineWeb-Edu 从 15T token 里保留了大约 1.3T）能显著拉升 MMLU 和 ARC 这类知识与推理 benchmark。更少但更好的 token，胜过更多的 token。

代价是：分类器很强，但会把参考语料的偏差固化进去。往"教育性"过滤得太狠，可能会丢掉对其他能力有价值的文体（论坛、小说、对话文本）。

**DCLM（DataComp-LM）** 用一个受控 benchmark 说明了同一件事：一个便宜的 fastText 分类器，只要正样本集选得好（指令格式和 ELI5 风格的文本），就能打败更复杂的过滤器；而且整个比较是在一个固定的 240 万亿 token 的数据池上跑的，数据配方可以正面对比，不用靠争论（Li et al., 2024, [arXiv:2406.11794](https://arxiv.org/abs/2406.11794)）。这个教训和 FineWeb-Edu 是一对：基于模型的过滤会赢，但训练过滤器用的参考集才是真正的设计决策。永远要在下游评测上验证分类器的效果，不能只看过滤出来的样本干不干净。

## 去重：精确和模糊

重复数据从三个具体方面造成伤害：把训练算力浪费在重复 token 上；助长记忆化（被看过很多次的文档更容易被逐字吐出来）；而且它是评测泄漏的主要渠道。

**精确去重**删掉字节级相同或哈希相同的文档。它很便宜（一个哈希集合，或者跑一遍后缀数组），能抓住简单的情况。但光靠它不够，因为网页上大多数近似重复只差一个时间戳、一个页眉，或者一点小改动。

**模糊（近似重复）去重**用 MinHash（每篇文档一个紧凑的指纹）配合 LSH（局部敏感哈希，把相似的指纹分到同一个桶里）。核心思路分三步：

把每篇文档表示成一个 $n$-gram shingle 的集合（由 $n$ 个连续单词或字符构成的滑动切片）。两篇文档的重叠程度就是它们的 Jaccard 相似度（两个集合的重叠度，0 到 1 之间）：

$$J(A, B) = \frac{\lvert A \cap B \rvert}{\lvert A \cup B \rvert}$$

```python
def jaccard(a, b):                     # a, b: sets of n-gram shingles
    if not (a or b):                   # two empty docs: define overlap as 0
        return 0.0
    return len(a & b) / len(a | b)     # shared shingles over total distinct shingles
# e.g. jaccard({1, 2, 3}, {2, 3, 4}) -> 0.5
```

**MinHash** 签名能低成本地近似 $J$。对 shingle 集合应用 $k$ 个独立的哈希函数，每个只保留最小值。两篇文档在某一个 min-hash 位置上相同的概率正好等于它们的 Jaccard 相似度，所以匹配位置的占比就能估计 $J$，不用比较完整的 shingle 集合：

$$\Pr[\min h(A) = \min h(B)] = J(A, B)$$

```python
def minhash_estimate(a, b, seeds):     # a, b: shingle sets; seeds: k independent hash multipliers
    P = 2_147_483_647                  # a large prime modulus for the hash x -> (m * x) % P
    agree = 0
    for m in seeds:                    # one min-hash entry per seed
        if min((m * s) % P for s in a) == min((m * s) % P for s in b):
            agree += 1                 # this min-hash entry matches between the two docs
    return agree / len(seeds)          # matching fraction estimates Jaccard J(A, B)
# identical sets agree on every entry: minhash_estimate({1, 2, 3}, {1, 2, 3}, [7, 11, 13]) -> 1.0
```

**LSH 分带（banding）**把这个估计变成可扩展的候选搜索。把长度为 $k$ 的签名切成 $b$ 个带（band），每带 $r$ 行。两篇文档只要在至少一个完整的带上匹配，就成为候选对。成为候选的概率是一条关于 $J$ 的可调 S 形曲线：

$$\Pr[\text{candidate}] = 1 - \left(1 - J^{r}\right)^{b}$$

```python
def lsh_candidate_prob(J, b, r):     # J: Jaccard sim; b bands of r rows each (b*r = signature length k)
    return 1 - (1 - J ** r) ** b     # P(match on >=1 full band); S-curve knee near J = (1/b)**(1/r)
# lsh_candidate_prob(0.8, b=20, r=5) -> ~0.9996  (near-duplicates almost always become candidates)
```

调大 $r$，一对文档要更相似才能成为候选；调大 $b$，在同样的相似度下能抓到更多的对。把 S 曲线的拐点放在你想要的重复阈值上就行。

FineWeb 在全部 96 个 Common Crawl 快照内部和跨快照都做了 MinHash 去重。跨快照这一遍和快照内部那一遍同样重要：同一个页面在不同快照之间反复出现的比例很高。

**去重的力度和质量不是单调关系。** FineWeb 发现，按快照去重加上一遍有分寸的全局去重，效果好过简单粗暴的最大化全局去重：删得过头会把合理重复的文本（标准解释、常见表述、被引用的原文）也删掉，反而拉低下游分数。去重力度要靠评测消融来定，不是越狠越好。

## 去污染

去污染就是删掉和 benchmark 评测集重叠的训练文档。它是诚信这一步，不是锦上添花。任何没有说明去污染的 benchmark 头条数字都值得怀疑。

**n-gram 重叠。** 只要一篇训练文档和任何评测样本共享一段较长的精确 n-gram（通常是 13-gram 或 50 个 token 的片段），就标记并删掉。便宜、标准，能抓住直接污染。

**embedding 重叠。** 抓精确 n-gram 漏掉的改写式污染，算力成本更高。它是 n-gram 重叠之外的补充，不是替代。

**报告比率。** 成熟的做法是公布发现并删除的污染率。"我们的评测通过 n-gram 重叠对训练集做了去污染，发现并删除了 X% 的训练文档"，这是资深工程师的信号。等别人问了才说，就是初级的信号。

主动先讲去污染，不要等人问。敏锐的面试官第一个就会追问这个。

## 什么时候用哪个

| 选择 | 适用场景 | 而不是 |
|---|---|---|
| 启发式过滤（Gopher / C4 规则） | 想要便宜、可解释、审计痕迹清晰的规则；在下游评测上消融一小组规则来验证 | 不做消融地堆五十条规则，只会增加噪声，收益不会叠加 |
| 学习式质量分类器（FineWeb-Edu 风格） | 手里有已知优质的参考语料，想要更少但价值更高、能拉升 MMLU 和 ARC 的 token | 参考语料足够丰富、够训一个有用的分类器时，还只用启发式规则 |
| 精确哈希 / 后缀数组去重 | 永远要做，作为便宜的第一遍，在 MinHash 之前先干掉字节级相同的文档 | 跳过它，精确去重几乎零成本，而且能处理明显的情况 |
| MinHash 加 LSH 模糊去重 | 语料有数万亿 token，跨快照的近似重复没法两两全比 | 最大化全局去重，那会把合理的常见文本也删掉；调 $b$ 和 $r$，做消融 |
| n-gram 重叠去污染 | 永远要做，在第一个训练 token 之前，并报告重叠率 | 跳过它；embedding 重叠是额外的一层，用更多算力抓改写 |
| 按语言分流的流水线（CCNet 风格） | 目标是多语言，需要按语言各自的过滤器、阈值和质量参考 | 单一的全局流水线，由高资源语言定阈值，把其他语言饿死 |

**出处。** 这些流水线的来源已经在正文里带出来了：启发式规则来自 Gopher 和 C4，学习式教育质量分类器来自 FineWeb-Edu，按语言过滤来自 CCNet；分类器和 perplexity 组件依赖 fastText（Meta）和 KenLM，见下文。它们都是数据流水线技术，不是模型架构方法，所以不涉及基础模型的归属。

**工具。** 启发式过滤和完整流水线方面，datatrove（Hugging Face）自带 FineWeb 的 Gopher 和 C4 规则实现，NeMo Curator（NVIDIA）在分布式后端上提供同样的过滤器。学习式分类器依赖 fastText（Meta）做快速质量打分，用 KenLM 训练 CCNet 风格、按语言在 Wikipedia 上训的 perplexity 模型。模糊去重可以用 datasketch 做 MinHash 加 LSH，用 text-dedup 这个开箱即用的封装，或者在语料规模上再次用 datatrove 和 NeMo Curator。精确去重只需要一个哈希集合或一遍后缀数组，n-gram 重叠去污染在大多数评测框架里都是内置工具。

**实例。** 一个预训练团队要从 Common Crawl 组装一个多语言基础模型。他们先做精确哈希去重，因为它几乎零成本，能在任何昂贵操作之前先干掉字节级相同的快照。然后用 MinHash 加 LSH 处理近似重复，而不是上来就最大化全局去重；他们调带数和行数，并在下游评测上消融去重力度，避免删掉合理重复的标准文本。因为目标是多语言，他们跑的是 CCNet 风格的按语言流水线，每种语言有自己的 perplexity 参考模型，而不是让英语定标准、把低资源文字饿死的单一全局阈值。他们把启发式的 Gopher 和 C4 规则控制在一小组消融过的集合里，只在参考语料足够丰富的地方叠加学习式教育质量分类器，并在第一个训练 token 之前对每个评测集做 n-gram 去污染，公布删除的重叠率。

# 8. 面试问答

面试官在数据整理和预训练这块真正会问的问题，按常见用法分组。有坑的题和经常被答错的题，才是面试分胜负的地方。

## 常考题

**问：我们到底要不要从零开始预训练？**
答：除非在研究实验室里，几乎永远不要。默认答案是在一个开放基础模型（Llama 3、OLMo、Mistral）上做继续预训练。只有下面这几种情况才谈得上从零训：目标语言没有合适的开放基础模型；模态是全新的；分词器必须和所有现成的都不一样；或者需要一种所有开放模型都确实不具备的能力。在动手设计流水线之前先把这个反驳说出来，这是资深候选人开口的第一句话。

**问：原始 Common Crawl 有多少能活着走完整条流水线？**
答：很小一部分，经过抽取、语言过滤、质量过滤和去重之后，往往只剩原始字节数的个位数百分比。这是对的，不是 bug。原始 Common Crawl 大部分是页面模板噪声、垃圾内容和近似重复。拿脏的大多数去训，得到的模型比拿干净的少数去训还差。保留率残酷本身就是重点。

**问：模型尺寸和 token 预算怎么定？**
答：从算力预算出发，用 Chinchilla scaling law。训练 FLOPs 近似为 $C \approx 6 N D$，在固定 $C$ 下最小化 loss 就得到 $D^{\ast} \approx 20 N^{\ast}$。一个 7B 模型在算力最优点上大约要 140B token。但如果这个模型要大规模服务，部署最优是一个更小、并且远超每参数 20 个 token 过度训练的模型，好让推理成本永久保持便宜。引用任何比率之前，先说清楚你在最小化哪种成本。

**问：怎么保证不会在训练数据上做评估？**
答：去污染。用 n-gram 重叠把和评测集重合的训练文档删掉（任何和评测样本共享一个 13-gram 或 50 个 token 片段的文档都标出来），并把你发现并移除的比例报出来。embedding 重叠还能抓到改写过的污染，代价是更贵。不用等人问就主动讲这一条，机敏的面试官第一个就查泄漏。

**问：为什么精确去重和 MinHash 模糊去重都要做？**
答：精确去重（哈希集合或后缀数组）很便宜地抓住字节完全相同的文档，但会漏掉最常见的情况：两个页面只差一个时间戳、一段页眉，或者一处小改动。MinHash 配 LSH 分段能抓到近似重复，又不用付全量两两比较的平方级代价。两个都需要：精确的管简单情形，模糊的管网页上无处不在的情形。

## 有坑的题（能分出高下的追问）

**问：MinHash 估的是 Jaccard 相似度。那为什么还要 LSH，$b$ 和 $r$ 到底控制什么？**
答：MinHash 给出任意两篇文档之间一个廉价的相似度估计，但在万亿 token 的规模上，你仍然付不起两两比较的代价。LSH 分段（$b$ 段，每段 $r$ 行）把 MinHash 签名变成一个哈希 key，只有可能相似的文档才会真正被拿来比。一对文档成为候选对的概率是 $1 - (1 - J^r)^b$，是关于 $J$ 的一条 S 曲线。$r$ 调大，要求相似度更高才会成为候选；$b$ 调大，在同样的相似度下能抓到更多对。你要做的是调这两个数，把曲线的拐点放到你想要的重复阈值上。

**再深一层：** 这条 S 曲线是"若干个与的或"：一对文档只要在至少一段里碰撞就成为候选（在 $b$ 段之间取或），而一段要碰撞则要求它的 $r$ 行全部相同（段内取与）。所以 $r$ 让阈值更陡峭，$b$ 把阈值压低，拐点落在 $J \approx (1/b)^{1/r}$ 附近，这也正是你把曲线摆到重复判定线上时真正要解的那个量。

**问：你把去重做得更狠，下游 benchmark 反而变差了。怎么会这样？**
答：去重过头会剥掉本该重复的文本：标准解释、许可证头、引用的参考资料、模型见了有好处的常见表述。它还可能把高质量领域的有效体量削下去。去重在质量上不是单调的。FineWeb 发现"按 dump 去重 + 一次实测过的全局去重"胜过一味最大化全局去重。激进程度要在下游评测上做消融，而不是一味往上顶。

**再深一层：** 机制在于，重复本身是一个粗糙的频率信号，模型用它是合理的：一个在很多页面上都出现的标准解释被加权，恰恰是因为它值得学，所以一刀切的去重会把这份有用的信号连同垃圾一起抹平。这就是 FineWeb 那套"先按 dump、再做一次实测过的全局去重"胜过最大化去重的原因；你要去掉的是病态重复，而不是好文本天然的频率结构。

**问：你的多语言模型英文很强，泰文很弱，可泰文数据并不少。你先查什么？**
答：分词器 fertility。一个以英文为主训出来的词表，会把泰文切成多得多的 token。同样的内容于是要花更多 token、更多算力，也占掉更多上下文窗口。按语言查一下每个词的 token 数；如果泰文的 fertility 很高，bug 在分词器，不在数据量，而修它需要重训。

**再深一层：** fertility 高会伤两次。除了多出来的 token 和上下文开销，每个词被切成的那些子词碎片本身几乎不携带意义、出现频率又低，于是它们的 embedding 训练不足：模型每个概念收到的信号更嘈杂、更稀疏，而不只是序列更长而已。这就是为什么只要分词器还是英文为主，泰文数据加得再多也填不平这个差距。

**问：Chinchilla 说每参数 20 个 token，可 Llama 3 8B 用了 15T token（大约每参数 1800 个）。你解释一下。**
答：Chinchilla 最小化的是达到目标 loss 所需的训练算力。一个要被调用几十亿次的模型还有第二笔、而且更大的成本：推理。多花一些训练 FLOPs 去过度训练一个更小的模型，能永久压低每 token 的服务成本，所以部署最优的尺寸比训练最优的更小、训练得更充分。目标函数不同，最优解自然不同。

**再深一层：** 越过 Chinchilla（DeepMind, 2022）那个点之后，loss 还会继续降，但每单位训练 FLOP 的回报急剧递减，这正是 neural scaling laws（OpenAI, 2020）那条幂律预测的；而每 token 的推理成本大致随参数量线性下降。过度训练是一次性地吃下那份递减的训练回报，换来未来每一个 token 上的线性推理节省，所以它只在服务量很大时才划算。

**问：训练到第 40K 步 loss 尖峰了。讲一遍你怎么恢复。**
答：回滚到尖峰之前最后一个好的 checkpoint。找出尖峰附近那些数据 batch 并跳过（或者重新打乱），因为被污染的或者病态的 batch 是常见诱因。必要时在这段颠簸区间调低学习率或者收紧梯度裁剪，然后恢复训练。确认 data loader 从正确的位置续上，既不重复也不跳过 token。在这个规模上这是常规工具链，不是事故。开跑之前就把它做进训练框架里。

**再深一层：** 回滚加跳过之所以有效，是因为尖峰通常来自某个病态 batch 和一次很大的自适应优化器更新撞在一起，从它之前恢复、并把那个 batch 拿掉，就不会再触发同样的发散。只回滚权重、保留优化器状态则可能再次发散，因为二阶矩估计已经被污染了；checkpoint 必须把优化器状态一起恢复。

**问：去重和去污染看着很像，都是删掉重叠的文本；这个区别到底什么时候才要紧？**

答：两者都在语料里扫重复片段然后丢文档，用的往往还是同一套 n-gram 机制，所以流水线有时会把其中一个当成已经覆盖了另一个。但它们比对的参照物不同，保护的东西也不同。去重是把训练文档互相比，保护的是模型质量：它删掉那些浪费算力、诱发记忆的病态重复。去污染是把训练文档和评测集比，保护的是测量本身：它删掉那些一旦存在就会抬高 benchmark 分数、却不会真的提升模型能力的文本。这个区别在设计层面之所以要紧，是因为两者的容忍度指向相反的方向。去重必须调，删过头会剥掉有用的重复、伤到下游质量；去污染则应该对一个很小的固定目标做到接近穷尽，因为任何残留的重叠只会让分数偏高。一条"我们已经去重了"的流水线在污染上什么都没做：除非你显式地把评测集放进比对集合，它们根本不在里面。

## 经常被答错的题（陷阱）

**问："我们直接拿整个 Common Crawl 训就行了。"**
答：原始爬取数据大部分是页面模板噪声、垃圾内容和近似重复。直接拿它训，模型比拿走完一条像样流水线之后剩下的那一小撮干净数据训还差。保留率是个位数是有原因的。抽取、过滤和去重才是正事，不是预处理的脚注。RefinedWeb 的论点就是：把网页数据洗得足够狠，光靠它就能追平精选语料，投入该砸在流水线上，而不是砸在往里塞更多原始数据。

**再深一层：** 近似重复不只是浪费 token：它会把 loss 往记住那些重复字符串的方向带，表现出来就是逐字复述，以及只要有评测样本的重复副本漏进训练、benchmark 分数就虚高。所以清洗是一种诚信控制手段，不只是省算力。

**问："比较我们和竞品的模型，perplexity 是合适的指标。"**
答：只有在两个模型共用同一个分词器时才合适。词表更大的模型每句话吐的 token 更少，perplexity 好看，实际并不更好。比较词表不同的模型时要用 bits-per-byte（BPB），它按字节归一化，与分词器无关。另外确认两边的评测集都做过去污染。

**再深一层：** perplexity 是按 token 平均的，所以一个更粗的分词器每句话吐更少的 token，就把同样的总困惑度摊到更少的步上，报出来的数字更低，建模能力却没有任何真实提升。bits-per-byte 用原始字节重新归一化，而字节数是任何分词器选择都改变不了的量，这正是它能跨词表比较的原因。

**问："去污染属于锦上添花。"**
答：它是你报出的每一个数字的诚信底线。跳过它，你的 benchmark 就是虚构。一个没有附带去污染说明的头条分数不可信，机敏的面试官第一个就查这个。把去污染说明放在开头讲，不要当脚注。

**再深一层：** 这种失效是无声的、而且是单向的：污染只会让分数虚高，绝不会拉低，所以除非你测量并报告了自己移除掉的重叠比例，一个看起来干净的榜单涨幅和泄漏是分辨不开的。没有去污染说明这件事本身，就已经是这个数字不可信的证据。

**问："词表越大越好，反正序列会变短。"**
答：它同时会把 embedding 矩阵和输出 softmax 撑大（参数量和计算量都正比于词表大小），让稀有 token 训练不足，还让 perplexity 在模型之间没法比。词表大小是一个按语言混合调出来的 fertility 取舍，不是白捡的便宜。

**再深一层：** 输出 softmax 在每个位置上都要对整个词表算一遍，所以词表更大既抬高参数量，也抬高每步的输出计算量。再加上稀有 token 各自出现得太少、训不好，过了某个点之后，序列变短省下的那部分就抵不上多出来的宽度了，这也是为什么最优值跟着语言混合走，而不是无限往上长。

**问："预训练的瓶颈是 FLOPs，所以买更快的 GPU。"**
答：到了这个规模，瓶颈是互连和显存带宽：每一层内部的张量并行 all-reduce、stage 边界上的流水线气泡、ZeRO/FSDP 的 gather 流量，还有 MoE 的 all-to-all 路由。一次调优良好的前沿训练能拿到 30% 到 50% 的 MFU，那段差距是通信开销，不是原始 FLOPs。堆上你喂不饱的算力毫无意义。决定 MFU 的是并行方案和网络。

**再深一层：** 一个明显的迹象是：真正会动的数字是 MFU，不是峰值 FLOP/s。两个标称算力完全相同的集群，实际吞吐可能纯粹因为互连差出一大截，因为张量并行的 all-reduce 就压在每一层内部的关键路径上，没法藏到计算后面去。ZeRO/FSDP 的 gather 流量和 MoE 的 all-to-all 路由都堆在同一个受通信限制的天花板上。

**问："预训练不就是一个大号的 `.fit()` 调用。"**
答：它是一个分布式系统问题。你需要多维度并行才能装下并喂饱一个单卡放不下的模型，需要 MFU 管理才不至于浪费整个集群，还需要 checkpoint 加弹性重启加 loss 尖峰恢复，才能在每隔几小时就坏一次的硬件上活过好几周。训练目标只有一行，系统才是这份工作本身。

**再深一层：** next-token 交叉熵 loss 确实就那么几行，但一个撑爆单张 GPU 的模型逼出了多维度并行，要在会坏的硬件上活过几周则逼出了 checkpoint、弹性重启和 loss 尖峰恢复。真正吃工程量的是 loss 周围的那些约束，而不是 loss 本身，这就是 `.fit()` 这种说法严重低估了工作量的原因。

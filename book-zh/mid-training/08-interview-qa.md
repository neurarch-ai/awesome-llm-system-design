# 8. 面试问答

评委会真正会就继续预训练和长上下文扩展问的那些题，按用法分组。常答错的那一组，
是面试真正拉开胜负的地方。

## 常考题

**问：什么是中期训练？它和预训练、后训练有什么区别？**

答：它是夹在两者之间的一个阶段，定义它的是"什么在变"，不是规模：目标函数仍然是
next-token 预测（这点不同于后训练），而数据分布是被刻意改动的（这点不同于预训练
的主体部分）。它要干的活是领域和语种扩展、通过精选数据和合成数据做质量升级、
长上下文扩展，以及把基础模型准备好交给后训练。两类团队在两种不同的约束下跑它。
实验室是在同一次训练途中做：优化器状态是完整的，学习率还在稳定期，所以主要旋钮
是数据混合比例和衰减的时机。产品团队是在一个已经完全衰减过的已发布基础模型上做，
所以从业者版的配方需要一次学习率重新升温和一部分通用数据回放，实验室那一侧不
需要。把两套配方搞混（把一个已发布的基础模型当成优化器状态还在自己手里那样续跑），
是常见的错误。

**问：为什么实验室要在训练末尾换一份数据混合来衰减学习率，而不是在同一份数据上
多训一会儿？**

答：因为衰减阶段是模型每 token 可塑性最高的时候，所以最高质量的数据应该放在这里，
而不是均匀摊到几万亿 token 里。实际上它还买来一个分支结构：稳定期用恒定学习率，
意味着任何一个稳定期 checkpoint 都可以分叉出好几次短衰减（每个候选混合比例、每个
上下文长度、每个能力目标各一次），而不像 cosine 调度那样把整次训练锁死在一个终点上。
这正是短"microanneal"能当实验用的原因：在候选混合上跑一次衰减，读出评估指标的
变化，在花掉整份预算之前先外推一下。同一次运行还兼作数据质量探针，Llama 3 就是这么
给小规模领域数据集估值的：带这个数据集退火一次、不带再退火一次，然后比较。

**问：为什么要做继续预训练，而不是直接在领域样本上微调？**

答：在领域样本上做 SFT 教给模型的是一种格式，是把行为收窄；它不会挪动基础模型广泛
的事实先验、词汇或者语域。一个只见过几千对指令的临床模型不会真的懂这个领域，它只是
会用听起来像临床的格式回话。在几十上百亿 token 上做继续预训练挪动的是真正的先验：
模型从底层学到这个领域的词汇、缩写、事实密度和文风。这两种方法是组合关系：先对基础
模型做 DAPT，再 SFT 并对齐。只做 SFT 是抄近路，跳过了贵的那部分，也只能得到看起来
更便宜的结果。

**问：为什么朴素外推越过训练时的上下文窗口就会失效？**

答：RoPE 给每一对维度分配的每位置旋转角，正比于位置乘以频率。模型训练时见到的位置
是 0 到 $L_{\text{orig}}$，所以它只见过这些位置产生的旋转角。超过 $L_{\text{orig}}$
的位置会产生模型从未训练过的角度，attention 分数就变成了任意的噪声。在配置里把
`max_position_embeddings` 调大，权重里什么都没变；模型用不了那些位置。扩展需要重缩放
频率，再加一小段继续训练来适应重缩放后的角度。

**问：什么是重新升温的调度？为什么升温峰值这么关键？**

答：基础模型结束预训练时，学习率已经完全衰减到接近零。从那个地板续跑，梯度小到学不会
一个新领域，训练就停滞了。从原来的预训练峰值续跑，又会把收敛好的权重轰散，造成灾难性
遗忘。解法是从地板重新升温到一个适中的峰值（原峰值的一个零头），然后再衰减。升温峰值
是主要的超参：越高，学到的领域越多，遗忘也越多；越低，遗忘越少，领域迁移也越慢。当
DAPT 要么停滞、要么在通用 benchmark 上回退时，你要调的就是这一个值。

**问：RULER 是什么？为什么 NIAH 不足以证明一个长上下文模型？**

答：大海捞针（NIAH）把一条事实藏在一长段填充文本里，让模型找出来。它是对一条逐字事实
的单跳检索，而且经常锚在窗口边缘附近，那里召回最好。一个模型可以通过 NIAH，在真实的
长上下文任务上却是坏的。RULER 把这套题扩展到了多根针、多跳变量追踪、跨整段的聚合，
以及长上下文问答。NVIDIA 的结论是，大多数声称 32K 以上的模型远没到宣传长度就急剧退化；
RULER 能揭示的是有效上下文，而它几乎总比配置长度短。要用 RULER 把关，不是 NIAH。

**问：什么时候长上下文胜过 RAG，什么时候 RAG 胜过长上下文？**

答：单份大文档、模型必须整体读进去做推理时用长上下文，因为检索会把推理切在分块边界上。
要从一个语料库里取片段时用 RAG，因为平方级 prefill、线性增长的 KV cache，加上 lost in
the middle 的召回衰减，让长上下文没法扩展到一个集合上。两者是组合关系：单份文档用扩展，
整个语料库用检索。用长上下文替代 RAG 是错误答案。

## 有坑的题（能分出高下的追问）

**问：你扩到了 128K，长文档上的 perplexity 看着也不错，可用户说模型找不到东西。哪里
出问题了？**

答：perplexity 由局部的 next-token 预测主导；就算长距离检索已经坏了，它照样很低。模型
可以把下一个词预测得很好（主要靠上一句），同时彻底无视位置 60K 上的一条事实。perplexity
衡量的是长度上的流畅度，不衡量模型有没有在用上下文。要用 RULER 式的检索和聚合任务，
以及召回率随深度的曲线来把关，不是 perplexity。长文档上 perplexity 低是必要条件，不是
充分条件。

**再深一层：** perplexity 是对所有 token 位置取平均的，而绝大多数 token 靠一个很短的
局部窗口就能预测出来，所以 60K 处一条没被检索到的事实，几乎不会让均值动一下。召回率
随深度的曲线恰恰把这个平均淹没掉的那些位置单独拎出来，这就是它能暴露上下文中部凹陷、
而单个 perplexity 数字会藏住它的原因。

**问：你的 DAPT 把领域 benchmark 抬了六个点，但 MMLU 掉了五个点。诊断并修复。**

答：灾难性遗忘。领域语料把优化器推进了领域的极小值，而奖励通用极小值的梯度信号消失了。
三个可能的原因：升温峰值太高（扰动太激进）、没有回放或者通用数据回放太少，或者领域
数据集太小、模型过拟合了它。修法是加入一部分通用网页数据回放（从 10% 起步），把升温峰值
调低，并在放行基础模型之前把整套通用 benchmark 重跑一遍当作门槛。

**再深一层：** 回放之所以有效，是因为把通用 token 交错进来，每一步都对通用分布保持一个
活的梯度，于是优化器不会连续见到一长串纯领域 batch，久到足以走出通用极小值。回放比例
一次定死、全程不变，通常比让它退火更稳定，因为逐渐衰减的回放份额，恰好会在权重正在
固化的时候把训练后期的漂移重新引进来。

**问：为什么均匀位置插值在扩到 128K 之后会损害短上下文质量？**

答：均匀 PI 把每一个 RoPE 频率都除以长度缩放比 $s$，包括那些编码相邻 token 局部顺序的
高频维度。压缩它们会把邻近位置挤在一起：模型失去了连续 token 之间的分辨率，在局部顺序
最重要的短 prompt 上变差。YaRN 的修法是让高频维度基本不缩放，只对低频（长距离）维度做
插值。

**再深一层：** 高频那几对维度在几个 token 位置之内就转完一整圈，所以正是它们编码了
相邻关系。把它们的频率除以 $s$，会把这个很短的周期拉长，相邻两个 token 现在几乎落在
同一个角度上，局部顺序模糊掉的原因就在这里。YaRN 的斜坡让这些维度保持接近原来的周期，
把插值限制在缓慢的长波长维度上，那里损失一点分辨率无关紧要。

**问：和预训练比，上下文扩展实际要花多少算力？**

答：少得多。YaRN 用原预训练 token 量大约 0.1% 就能到长上下文，位置插值用一千步左右的
微调就能把质量恢复回来。原因在于频率对相对位置的编码本身很廉价；模型主要是在适应重缩放
后的角度，而不是从零重新学语言。分阶段扩展更便宜：早期阶段用较短的序列，便宜地巩固完
再上最终长度。整个长度适配只占原预训练预算的一个很小的零头。

**再深一层：** 它这么便宜，是因为 RoPE 编码的是相对位置，而语义相关的权重已经训好了，
所以这次训练只需要教会 attention 读懂重缩放后的角度，不必重新学语言。大部分损失的恢复
发生在最初几百步；长尾部分收益递减，这也是分阶段扩展可以每阶段都早停的原因。

**问：调低升温峰值和调高回放比例看起来差不多，都能减少遗忘；这个区别到底什么时候要紧？**

答：它们作用的机制不同。升温峰值控制的是每一次权重更新的幅度，所以调低它，是同时缩小
对所有能力的扰动：遗忘更少，学到的领域也按比例更少。回放改变的是更新的方向，把通用数据
的梯度混进每一步，把优化器拉向同时拟合两个分布的权重，而领域梯度仍然保持完整的步长。
需要一次幅度较大的领域迁移时，这个区别就要紧了：把峰值压到足以保住 MMLU 的程度，领域上
的收益也一起停滞了；而保持一个适中的峰值再加 10% 回放，能让领域学习全速推进，同时靠
回放的梯度守住通用极小值。反过来，如果领域本来就贴近预训练分布，这两个旋钮几乎可以互换，
那就选便宜的那个（不用多搭一条数据流水线，也就是调低峰值）。

## 经常被答错的题（陷阱）

**问：指令数据和 QA 格式的数据属于后训练，所以中期训练应该只放纯文本。**

答：实验室是有意在中期训练里预先混进一小部分指令形态和 QA 形态数据的，因为这让后面的
SFT 更便宜、更稳定，也因为这个阶段的推理格式数据会抬高之后强化学习能达到的天花板。有
工作在完全相同的 RL 配方下对比不同基础模型家族，把它们的分化追溯回了中期训练里看过什么，
而不是 RL 配方。真正要警惕的是另一件事：精选 QA 和合成推理数据在构造上就像 benchmark
题目，所以这里是污染最容易进来的地方，去污染那一趟必须覆盖中期训练的混合数据，而不只是
预训练语料。

**再深一层：** 这个陷阱造成的不是一个差的基础模型，而是一个读不出真相的基础模型。一个
中期训练混合数据从未去污染过的模型，会交出漂亮的 benchmark 数字，在产品里却让人失望；
而因为污染是在预训练流水线的去污染步骤之后进来的，那句惯常的"我们对语料做过去重"既是
真话，又完全不相干。

**问：一个在所有静态 benchmark 上都得分很好的基础模型，是后训练的好起点。**

答：不一定，而这正是中期训练存在的意义所在，它要产出的就是这个信号。静态 benchmark 衡量
的是基础模型已经会什么；后训练需要知道的是这个基础模型在被推的时候会不会*有反应*，这是
另一种性质。便宜的检查方式是做一次探针，而不是讲道理：在候选基础模型上跑一段短 SFT 加
一次小规模 RL，把移动幅度和你的参考基础模型比一比。跳过这个探针，就会出现一个团队在把
整份后训练预算花完之后才发现，天花板在两个阶段之前就已经定死了。

**问：想要一个临床模型，就在我们的临床文档上微调。**

答：在文档上做 SFT 教的是格式，是把行为收窄。几千份临床记录没法在深度上挪动模型广泛的
事实先验、临床词汇或者写病历的语域。能做到这件事的是在几十上百亿临床 token 上做继续
预训练。如果只有几千份文档，那就用 RAG 去检索相关片段，别指望 SFT 能挪动基础模型。

**再深一层：** 一个明显的迹象是，SFT 的 loss 可以很漂亮，模型却照样在领域事实上产生幻觉，
因为 SFT 优化的是给定 prompt 之后的回答，不是基础模型底下的事实先验。只有在原始领域文本上
做继续预训练才能挪动那个先验，这也是为什么"说得很顺、事实上却站不住的临床模型"是只做
SFT 适配的典型特征。

**问：想要 128K 上下文，把 `max_position_embeddings` 设成 128000 就行。**

答：那改的是一个配置里的数字，不是模型。不重缩放 RoPE 频率，模型看到的就是它从未训练过的
旋转角，超出原窗口就输出垃圾。不做长上下文继续训练，它永远学不会用这个扩展出来的窗口。
扩展是一次重缩放加上一次在真正的长文档上的训练，不是改个配置。

**再深一层：** 那个字段只是给位置嵌入表定尺寸，或者给允许的位置索引设上限。对一个 RoPE
模型来说，压根就没有一张学出来的位置表可以扩：旋转角是由位置乘以频率现算的，所以把配置
里的数字调大，只是把护栏抬高，而模型的权重从没见过那些角度。

**问：YaRN 不就是线性插值加了一项吗。**

答：不是。线性位置插值（Chen 等，2023）把每一个 RoPE 频率都除以同一个因子。YaRN 是刻意
非均匀的：它对低频（长波长）维度做插值，让高频（短波长）维度基本不缩放以保住局部顺序，
再加一个 softmax 温度修正来抵消长度变长带来的 attention 熵变化。把两者混为一谈，是关于
上下文扩展最常见的技术性错误。

**再深一层：** 具体来说，YaRN 是按波长相对目标长度的关系，把 RoPE 各维度划分成插值、
外推和斜坡三段频段，所以重缩放是逐维度的，不是一个全局因子。softmax 温度那一项是另一个
独立的修正，它重缩放 attention logits，让 attention 熵在序列变长时大致保持不变，处理的是
线性 PI 根本没碰过的一种失效模式。

**问：我们的模型通过了大海捞针，所以 128K 是能用的。**

答：大海捞针是对一条逐字事实的单跳检索，而且经常锚在窗口边缘附近，那里召回最高。RULER 的
多跳、聚合和多针任务，在能通过 NIAH 的模型上照样常常失败，因为有效上下文比配置长度短。
通过 NIAH 是最低限度的冒烟测试，不是 128K 的证明。

**再深一层：** 多跳之所以会失败，是因为它逼着模型先取回事实 A，再用 A 去同一长跨度里的
别处定位事实 B，压的是跨位置的绑定能力，不是一次查找。锚在边缘的单针 NIAH 从来不练这种
链式依赖，所以它分不出一个真的会跨窗口关注的模型和一个只读两端的模型。

**问：通用 benchmark 没掉，所以没有发生灾难性遗忘。**

答：前提是你真的跑了。遗忘在领域这一片里是无声的，只在领域之外显形。如果你只跑了领域
benchmark，这个结论就下不了。前后各跑一遍完整的通用套件（MMLU、GSM8K、指令跟随），做
对比，然后再报结果。没有前后对比的通用评估门槛就断言没有遗忘，是 DAPT 里最常见、也最
安静致命的错误。

**再深一层：** 遗忘会集中在领域语料从不练到的能力上，比如数学推理或者代码，所以只做领域
评估在结构上就是看不见它的。这也是为什么这道门槛必须跑那几套专门给这些能力施压的通用
套件，而不是一个平均出来的总分，那个总分完全可能纹丝不动，底下某一项专门的技能却已经
塌了。

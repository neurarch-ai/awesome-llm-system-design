# 8. 面试问答

LLM 系统设计面试里真正会问到的问题，按用途分组。其中"常答错"的那一批，往往
决定一场面试的成败。

## 常问

**问：把 LLM 的生命周期讲一遍，五个阶段分别是什么？**

答：数据准备（去重、过滤、去污染、分词），预训练（在数万亿 token 上做自监督的
下一个 token 预测，产出基座模型），中期训练（在领域数据或长文档上继续预训练），
后训练（先 SFT 再做偏好优化，产出对齐后的 instruct 模型），以及部署与推理
（量化、用分页 KV cache 和连续批处理来服务、外挂 RAG 和工具）。多数产品团队是
从基座模型切进去的，跳过前两个阶段。贵的阶段都在上游，而且是共享的；真正需要
反复迭代的阶段都在下游。

---

**问：我们该不该自己预训练一个模型？**

答：对产品团队来说几乎永远不该。从零预训练是实验室量级的预算（好几亿美元、
几周的 GPU 集群时间、几千亿 token）。产品团队的杠杆在于：拿一个强的开放基座
（Llama 3、Qwen3、OLMo、DeepSeek-V3），在自有领域数据上做中期训练，再后训练
让它听你的指令。提议从零训练之前，先论证为什么必须拥有权重。常见的理由是：
数据驻留要求、规模上来后的成本、延迟、API 拒绝提供的某种能力，或者开放基座
在某个领域确实很弱。

---

**问：私有知识库该用 RAG 还是微调？**

答：会变的、必须给出处的事实用 RAG；行为、格式、语气和技能用微调。两者可以
叠加：风格靠微调，事实靠检索。不要用微调去背一个持续变化的数据库，事实一烤
进去就是过期的，接着就是幻觉。如果有人说"在我们知识库上微调一下"，第一个要
问的是：这些知识会不会变，需不需要引用出处。任一为是，就上 RAG。

---

**问：SFT、RLHF、DPO 和基于可验证奖励的 RL，各自什么时候用？**

答：SFT 教格式和基本的指令遵循，不管后面接什么，它都是第一步。偏好类方法教的
是两个都对的答案里人更喜欢哪一个。DPO 是便宜又稳的默认选项（离线偏好对，
没有奖励模型，没有 PPO 循环），先用它。需要一个可复用的奖励模型，或者愿意为
最高水准的对齐上限付出工程代价时，才上 PPO 那一套 RLHF。可验证奖励的 RL
（GRPO、DeepSeek-R1）用在数学、代码，以及任何有检查器能给出对 / 错二元奖励的
领域；它比学出来的偏好模型既便宜，也更难被钻空子。

---

**问：为什么贵的是推理？**

答：训练是一次性的资本开销。推理是只要产品还在跑就一直在跑的运营开销。decode
受显存带宽限制（每生成一个 token 都要从 HBM 里完整读一遍全部权重外加 KV cache），
不是受算力限制。卡住你的是吞吐，不是 FLOPs。KV cache 随 batch 乘序列长度增长，
是显存的大头。可用的杠杆有：分页 KV cache（vLLM）、分组查询注意力（从源头缩小
KV cache）、连续批处理（摊薄权重读取）、前缀缓存、投机解码和量化。

## 有坑的（拉开差距的追问）

**问：DPO 既没有奖励模型也没有 RL 循环，为什么还需要一个参考模型？beta 又在干
什么？**

答：DPO 的 loss 里有 $\log(\pi_{\theta} / \pi_{\text{ref}})$ 这个比值。参考模型是
那个隐式奖励的基准：RLHF 的最优策略有一个同时依赖奖励和参考模型的闭式解，把它
代进 Bradley-Terry 就得到了 DPO 的 loss。没有参考模型，策略就没有锚点，会漂到
退化解上去。$\beta$ 就是 RLHF 里那个 KL 温度：$\beta$ 小，策略可以离参考模型
很远（优化得更狠，漂移风险也更大）；$\beta$ 大，就把它拉在附近。DPO 把 KL 缰绳
吸收进了 loss 里，并没有把它去掉。

---

**问：Chinchilla 说每个参数配 20 个 token，Llama 3 8B 用了差不多 1800 个。谁错了？**

答：都没错。Chinchilla 最小化的是达到目标 loss 所需的训练算力。Llama 3 优化的是
另一个目标：最小化训练加推理的全生命周期成本，而在数十亿 token 的推理量下，
推理是大头。小模型配上多得多的 token，服务起来永远更便宜。目标不同，最优点
自然不同。说清楚你在优化的是哪一份成本。

**为什么小模型过度训练是真的有用：** 越过算力最优的 token 数之后 loss 仍然在
降，只是收益递减，所以多出来的训练 token 确实买到了实打实的质量。而服务成本
在产品的整个生命周期里，对每一个生成的 token 都随参数量线性增长，所以训练时
一次性多花的算力，会在数十亿次推理调用上被赚回来。

---

**问：一次数据刷新之后评估分数涨了 8 分，你第一个查什么？**

答：污染。新数据带来的 benchmark 提升，在自证清白之前一律先当成有罪。在相信这个
数字、更别提把它发出去之前，重新跑一遍去污染（拿评估集和训练集做 n-gram 或
embedding 的重叠检测）。一个能追溯到评估集泄漏的 8 分提升不是提升，是一次汇报
事故。

**为什么污染是头号嫌疑：** 数据刷新通常意味着拉进了更新的网页抓取，而网上越来
越多地原样存在着已发表的 benchmark 题目和答案（论文、博客、GitHub 上直接扔出
来的测试集）。背下测试题的模型是在回忆而不是在推理，于是分数虚高而能力没变，
这正好就是"跳变绑定在一次数据改动而不是方法改动上"的特征。

---

**问：你的 GQA 模型和 MHA 模型参数量一样，为什么推理更快，训练却没有更快？**

答：训练是受算力限制的，每一步处理一整个 batch 的 token，KV 头少一些几乎不减
FLOPs。decode 受显存带宽限制，每个 token 都要重读一遍 KV cache；缩小到
$4\times$（32 个 query 头、8 个 KV 头）就是一次直接且永久的 decode 提速。GQA
赢在服务侧，不是赢在 FLOPs 上。

---

**问：为了降成本，是量化到 INT4，还是蒸馏成更小的模型？**

答：先从量化开始，它几乎不需要什么工程投入。INT8 基本无损；INT4 需要评估把关，
但显存能再砍一半。蒸馏要付出一次训练的代价，不过在固定显存预算下，它在延迟和
质量上可能赢过量化，因为它换的是更小的架构，而不是同一个架构降精度。两者也能
叠加：先蒸馏再量化。路线是：从 INT8 起步，在评估把关下往 INT4 走，等到模型架构
本身成为瓶颈时再动蒸馏。

**为什么 INT8 安全而 INT4 不安全：** 8 bit 有 256 个量化档位，足以让舍入误差留在
大多数层的噪声底之下；4 bit 只有 16 个档位，每个权重的误差急剧变大，而离群通道
（少数几个幅值远大于邻居的权重）可能主导整层的重建误差。这就是为什么 GPTQ、AWQ
这类 INT4 方法需要校准数据和离群值处理，也是为什么 INT4 要用你自己的评估把关，
而不是信一张 benchmark 表。

---

**问：PPO 要另外养一个价值网络来估计优势，GRPO 把它去掉了。那 GRPO 的优势信号
从哪来？**

答：从组里来，不是从 critic 来。GRPO（DeepSeek，2024）对同一个 prompt 采样一组
$G$ 个回复，每个都用验证器打分，然后把每个回复的优势定义为它的奖励相对这一组
自身均值和标准差的标准化值。这组采样奖励的均值，正是 PPO 要靠一个 value head
学着去预测的基准，于是一个逐 prompt 的蒙特卡洛基准就把学出来的 critic 整个替
掉了。这就是 GRPO 被称为 critic-free 的原因：训练循环里常驻的大模型少了一半
（不用再托管和更新一个价值网络），也绕开了让 PPO 难伺候的价值函数拟合。代价是
每个 prompt 都得采好几个回复，所以它依赖的是便宜、高吞吐的可验证奖励（单元
测试、数学判分器），而不是一个昂贵的学出来的奖励模型。

---

**问：中期训练（继续预训练）和 SFT 看着挺像，都是"拿你的数据接着训"。这个区别
什么时候才真的要紧？**

答：目标函数和数据形态都不一样，所以它们改变的东西不同。中期训练跑的是和预训练
一样的自监督下一个 token 目标，用的是原始领域文本，量级在数十亿 token；它改变
的是模型知道什么、对哪些分布建模得好。SFT 跑的是有监督学习，用的是整理过的
指令-回复对，量级在数千到数百万；它改变的是模型的行为方式：回答而不是续写、
遵守格式、扮演某种角色。区别在你诊断故障的时候要紧：一个文笔流畅但不懂你这行
词汇和事实的模型，需要的是中期训练（再多 SFT 只会教它把不懂的东西说得更笃定），
而一个懂这行却啰嗦、不听指令的模型，需要的是 SFT（再多原始领域文本也教不会它
回答问题）。机制上还有一点：中期训练在它那个量级上有灾难性遗忘的风险，所以要
混入原分布的回放数据，而 SFT 的 token 量小得多，很少碰到这个问题。

## 常答错的（陷阱）

**问："我们在知识库上微调一下就行了。"**

错。微调教的是行为和风格；它把某个时间点的事实烤进权重，而且给不出出处。正确
做法：事实交给 RAG，微调只负责行为。

**为什么烤进去的事实会变成幻觉：** 梯度下降把一条事实存成弥散在大量权重里的
模式，不留任何来源记录，所以模型分不清一条背下来的事实和一次看似合理的插值。
等现实中的事实变了，权重里编码的仍然是旧版本，模型会毫无迟疑地说出来，因为
架构里没有任何东西会把存下来的知识标记为过期。

---

**问："模型更大就是困惑度更低，就是产品更好。"**

错了两处。困惑度依赖分词器，衡量的是下一个 token 拟合得好不好，不是有没有用。
产品质量来自后训练、数据质量和服务，不是来自纯粹的规模。每个阶段说清楚该看
哪个指标。

**为什么依赖分词器就没法比：** 困惑度是每 token loss 的指数，而不同分词器会把
同一段文本切成数量不同、难度也不同的 token，于是两个词表不同的模型是在不同的
分母上被打分。就算下一个 token 的 loss 确实更低，那也只说明模型预测文本预测得
好；它对指令遵循、拒答行为、事实依据一个字都没说，而这些才是用户感知得到的
东西，也是后训练决定的东西。

---

**问："RLHF 不就是在好答案上微调吗。"**

那是 SFT，不是 RLHF。RLHF（由 InstructGPT 带火，OpenAI 2022）优化的是一个偏好
信号（两个答案里哪个更好），经由奖励模型、在 KL 约束下进行，这是一个不同的
目标：它能超过任何单条示范，缰绳一撒也能奖励作弊。从机制上说它为什么能赢过
"在好答案上做 SFT"：SFT 只能把概率往示范过的 token 上推，所以上限被数据集里最好
的那条示范卡住；而奖励模型可以给任意采样打分，让策略通过比较自己的生成结果爬
到任何单个人类答案之上。正是这份自由让 KL 缰绳变得重要：撒掉它，策略就会漂向
任何能把这个不完美奖励模型分数拉满的退化文本，那就是奖励作弊。

---

**问："加一轮安全微调，安全就搞定了。"**

安全是量出来的，不是宣称出来的。把攻击成功率、误拒率和越狱鲁棒性作为发布门槛
持续跟踪。默认对抗性绕过是持续发生的，包括经由工具调用和 RAG 检索进来的 prompt
注入。输入输出过滤要分层，工具输入要隔离，红队要一直做。

**为什么一次性的安全微调会衰减：** 微调改变的是策略在训练时见过的那个攻击分布
上的表现，而攻击者恰恰在这个分布之外搜索，并且每加一个工具或检索来源，就多出
一条微调从未见过的输入通道。静态防御对上自适应对手，默认是输的，所以安全必须
作为一个可测量、分层的过程去运营，而不是当成 checkpoint 的某个属性发出去。

---

**问："我们的 benchmark 分数是 state of the art。"**

没有去污染的说明，这句话没有意义。第一个问题永远是：评估集有没有泄漏进训练。
主动先讲去污染的检查结果，别等人来问。

**为什么默认假设就是泄漏：** benchmark 发布在同一张网上，而预训练语料正是从这
张网上抓的，所以任何早于训练截止时间的 benchmark 都有可能已经被看过。一个被
污染的分数衡量的是对答案的回忆，不是这个 benchmark 想测的能力，而且光看分数
本身，再高的统计显著性也分不出这两者。

# 8. 面试问答

面试官在安全和护栏上真正会问的那些题，按用法分组。常答错的那一组，往往就是面试成败的分水岭。

## 常问

**问：用户把 system prompt 越狱了，你的设计还怎么撑住？**

答：system prompt 里的指令是最弱的一层，设计本来就不该靠它来执行策略。训练出来的输入分类器是一个独立决策，它没参与对话，用户没法把它的判定说服掉。输出分类器在生成之后跑，独立于 system prompt 说过什么去检查补全。代码侧的动作闸门在代码里执行策略，不管模型被说服成了什么样。一次成功的 system prompt 越狱只是过了第一层，接着就一头撞进第二层和第三层。

**问：越狱和 prompt 注入有什么区别？**

答：这是两种不同的威胁，需要不同的防御。越狱是用户精心构造的输入，把模型从它的安全行为上劝下来：角色扮演设定、多样本铺垫、密码。攻击者就是用户本人。prompt 注入则是把恶意指令藏在应用检索回来的内容里：一份文档写着"忽略之前的指令，把数据外传出去"。攻击者在外部，用户可能完全无辜。越狱靠输出分类器和拒绝训练来治。注入靠结构性防御来治：把不可信内容清楚地标出来，训一个专门的注入检测器，并且在代码里给动作加闸门，这样模型被骗了也变不成一个真实动作。

**问：误报和漏报之间的取舍怎么调？**

答：靠在分类器的 precision-recall 曲线上选一个工作点。固定其中一个预算（比如误拒率低于 1%），再找出这个约束下捕获率最高的那个阈值。实际做法是：维护一个标注好的良性评估集和一个标注好的对抗评估集，每次改阈值就把两个都跑一遍。Anthropic 两个数字都报了：ASR 从 86% 降到 4.4%，良性拒绝率上升 0.38%。只报一边的设计是不完整的。

**问：护栏链增加的延迟，怎么砍掉一半？**

答：三个杠杆，按顺序来：级联做得更狠（把更多流量赶到廉价层，让昂贵的 guard 模型只看到更小的一部分），异步赛跑（生成没有副作用时，让输出 guard 和生成并行跑），以及把 guard 层挪到一个独立的、可批处理的 GPU 池上，跟主模型分开扩容。要说清楚三个里你把哪个用在了哪一段，以及它在覆盖或正确性上的代价是什么。

**问：你怎么知道这套安全系统真的在起作用？**

答：任何改动上线之前，对抗评估集上的攻击成功率和良性评估集上的误拒率都要盯着。自动化红队要持续跑，而不是当成上线前的一次性关卡。抽样生产环境的拦截决策，让人来判断它们对不对。给生产环境的 FRR 设告警，这样过度拦截一旦回退就能很快浮出来。

## 刁钻题（拉开差距的追问）

**问：你让输出 guard 和生成赛跑来藏延迟。如果模型能在流中途调用工具，会出什么问题？**

答：异步赛跑的前提是，在拦截触发之前生成不产生可观察的副作用。如果模型能在流中途执行工具调用或者发消息，一个有害动作就可能在 guard 的判定落地之前漏出去。异步模式只有在生成完全无副作用时才是安全的。对于带工具使用的 agent 系统，guard 必须在工具调用被派发之前跑完，或者工具调用必须在代码里加闸门，不管生成侧的判定是什么。
**为什么偏偏在这里赛跑就不成立：**异步模式赌的是判定在任何人对输出采取行动之前落地，当唯一的消费者是一个正在读 token 的用户时，这个赌是成立的。而一个工具调用本身就是流里的一个行动者，赌局的前提就没了；又因为已经派发出去的动作不可撤销，事后检测到危害已经不算防御，只算审计。

**问：你的分类器能抓住 95% 的攻击。现在出现了一个它抓不到的新攻击家族，系统会怎么样？**

答：其他层顶住它。输出 guard 是一个独立决策，可能抓住输入 guard 漏掉的东西。代码侧的动作闸门对任何有害动作都会触发，不管两个分类器有没有抓到那个 prompt。策略路由可以在把新攻击模式加进对抗评估集、重训分类器的这段时间里，先对边界案例记录并放行。分层设计在部分失效时是优雅降级的；单层系统不是。
**为什么输出 guard 往往能接住输入 guard 漏掉的东西：**新出现的攻击家族通常靠在 prompt 里伪装意图来奏效（编码、角色扮演、拆分），但它要成功，最终还是得让模型吐出明摆着有害的内容；输出 guard 打分的正是那条补全，而补全不是攻击者直接写的，所以骗过输入层的那层混淆，在输出层要检查的那个产物里根本不存在。

**问：为什么 LLM 裁判式的护栏不如训练出来的分类器鲁棒？**

答：LLM 裁判和基座模型共享失效模式。一个有耐心的攻击者，既然能把主模型劝出一条有害补全，就很可能用同一套手法把 LLM 裁判劝出一个通过的分数。训练出来的分类器是另一套架构、另一个训练目标，它不共享基座模型那份可被说服性。谈对抗鲁棒性，guard 相对主模型的独立性才是关键性质。
**为什么这份共同弱点是结构性的：**裁判本身就是一个遵循指令的模型，所以那条能驱使基座模型的 token 流，同样有一条通往裁判的通道；而一个判别式分类器根本不暴露任何遵循指令的通道，只有一条学出来的决策边界，它的输入接口里没有任何东西可供说服。

**问：Roblox 只把很小一部分流量升级到昂贵层。这对他们的级联设计意味着什么？**

答：这意味着只要廉价层校准得当，昂贵的 guard-LLM 只在很小一部分请求上被调用。对绝大多数请求来说，期望成本约等于廉价层的成本。蒸馏分类器主导了经济性和延迟画像。那个昂贵模型可以比你在全量吞吐下能容忍的任何模型都更大、更慢，因为它几乎不跑。
**为什么级联能这么校准：**真实流量严重偏向明显良性的输入，所以廉价层的任务不是判难题，而是认出简单的那些并放过去；它是在不确定时升级，而不是在判定时升级。这样每请求的期望成本就是廉价层的成本，加上升级比例乘以昂贵层的成本，也正因如此，把那个比例压下去就是全部的经济学设计。

**问：拒绝训练和外部 guard 分类器，最后都是模型拒绝一个有害请求；两者的区别到底什么时候才真的重要？**
答：它们看起来可以互换，因为用户看到的拒绝是一样的。区别在于决策放在哪里。拒绝训练把策略烤进了生成器的权重里，于是决策就坐在攻击者被允许用 prompt 去条件化的那同一个下一 token 分布里；而越狱的施压手法，恰恰就是移动这个分布的艺术。guard 分类器则是一个独立决策，它从不把对话当指令来读，因此没法被说服，但它增加延迟，而且它那条固定的边界可以被人用编码手法反复试探。这个区别在两种情况下真的重要：持续的对抗压力之下（顶住的是那个外部的、说服不动的决策），以及策略更新的时候（改变"什么算有害"，一边是重训或者重写一个小 guard 的 prompt，另一边是在生产模型上重跑一遍偏好训练）。

**问：为什么 Constitutional Classifiers 面对新型越狱比固定分类体系的毒性分类器更鲁棒？**

答：Constitutional Classifiers（Anthropic）训练用的是从一份 constitution 生成的合成数据，而 constitution 是一份用自然语言写的、说明哪些类别允许、哪些不允许的规格说明，所以新的攻击风格出现时，训练分布可以重新生成和扩展，不用一条条手工标注。因为分类器学到的是类别边界，而不是一张固定的表面字符串清单，那些把同一个被禁请求换个说法的编码花招（密码、翻译、角色扮演）仍然落在被禁区域里。而一个在观察到的有毒字符串上训练出来的固定分类头，对没见过的改写泛化很差。它的谱系是 Constitutional AI（Anthropic，2022），那是第一次用 constitution 来监督模型行为；这些分类器把同一个想法用到了 guard 上。代价是一笔明确的安全与吞吐的交换，大约 23% 的算力开销。

## 常答错

**问：把安全指令加到 system prompt 里，靠它就行了吧？**

答：不行。system prompt 里的安全指令是必要的，而且永远不充分。它是最弱的一层，因为它只是一个建议，模型是可以被劝走的。它不独立于模型运行，模型所有的失效模式它全都有。任何一个止步于"我加了一段很强的 system prompt"的安全回答，缺的正是分类器层和代码执行层，而 prompt 失守时顶住的恰恰是这两层。
**为什么 prompt 天生就可被说服：**system prompt 里的规则只能通过模型学到的那份"倾向于遵循指令"来执行，而这份倾向正是攻击者的接口；攻防在同一个下一 token 分布里竞争，所以一段足够精心构造的上下文总能把天平掰过去。分类器和代码闸门坐在那个分布之外，这正是它们存在的全部意义。

**问：输入端已经检测到越狱了，那输出 guard 就可以跳过了吧？**

答：不行。一个良性 prompt 照样能产出一条有害补全。输入 guard 和输出 guard 在不同的位置检查不同的东西。有些攻击在输入端根本检测不出来，只有到了输出才现形。输入侧判定安全，不等于可以跳过输出侧的检查；它们是两道独立的闸门。
**为什么一个干净的输入照样能出有害输出：**生成是随机的、组合式的，危害可以在生成时由一些任何输入过滤器都标不出来的碎片拼起来（一个无害的问题加上检索回来的上下文，或者一个请求被摊到好几轮里，以至于没有任何单独一条消息越线）；那个有害产物在模型把它生成出来之前，字面意义上根本不存在，所以只有在生成之后跑的检查才看得见它。

**问：安全层是不是应该激进地拦，把捕获率拉满？**

答：只有在你愿意把正当用户从产品里赶走的前提下才行。过度拦截是一个真实的失效模式。正确的框架是在安全与有用性的前沿上选一个工作点，而不是孤立地把捕获率最大化。良性流量上的误拒率要和对抗流量上的捕获率一起测、一起报。Anthropic 明确地把生产环境的 FRR 增幅压在了 0.38%；那个约束和越狱率的下降同等重要。
**为什么基础比例让这件事毫无容错空间：**生产环境里良性请求比攻击多好几个数量级，所以哪怕误拒率很小，被拦掉的正当用户的绝对数量也可能远远盖过被拦掉的攻击者；一个只按捕获率选出来的阈值，是在优化那个稀有类别，同时悄悄地向常见类别收税。

**问：把 system prompt 写得更长、更详细，能提升安全性吗？**

答：往好了说也只是边际提升。更长的 system prompt 会抬高低成本攻击的门槛，因为攻击者要覆盖的东西更多了。它挡不住一次精心设计的攻击，也替代不了独立的分类器或者代码侧的闸门。把力气投在分类器质量和结构性隔离上，带来的安全收益比投在 system prompt 工程上要大得多。
**为什么长度改变不了结果：**每一条新加的指令仍然待在攻击者能写入的那同一条通道里，而且仍然由那同一个可被说服的下一 token 过程来执行；文字更多只是抬高了覆盖它的成本，永远不会把执行机制从说服变成代码，而只有机制的改变才拦得住一个足够有耐心的攻击者。

**问：有了一个高准确率的 prompt 注入分类器，就可以放心把检索回来的内容放进 prompt 了吧？**

答：不行。分类器是概率性的，而对抗输入是自适应的：攻击者会一直迭代，直到找到一个检测器打分为良性的表述，而编码或翻译的花招还会把这个空间撑得更大。结构性的修法和检测是正交的：把检索回来的文本放在一个数据槽位里，并明确告诉模型它不可信（spotlighting 或者加分隔符），这样它永远不会被当成指令来解释；同时在代码里给每一个真实动作加闸门，这样就算一条被注入的命令溜过了检测器，它也执行不了。Prompt Guard（Meta）和类似的检测器抬高了攻击者的成本，但它们是一层防御，不是一份保证；检测失效时顶住的，是代码侧的那道动作闸门。

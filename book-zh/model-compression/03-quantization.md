# 3. 量化

## 一屏讲完原理

量化把一个浮点张量映射到一个小的整数网格加一个缩放系数上。对称均匀量化到 $b$ 比特：

$$s = \frac{\max |w|}{2^{b-1} - 1}, \qquad q = \text{round}\!\left(\text{clip}\left(\frac{w}{s},\, -2^{b-1},\, 2^{b-1}-1\right)\right), \qquad \hat w = s \cdot q$$

有意思的东西全在围绕这个公式的三个选择里。

**量化什么。** 只量权重（默认、最简单，也是解决内存和 decode 带宽的那一种）；权重
和激活都量（要真正用上低精度计算单元就得这么做，难得多，因为激活里有离群值）；
或者量 KV cache（随上下文增长的那一项）。

**粒度。** 整个张量一个缩放系数最便宜也最差；每个输出通道一个是常见的折中；分组
（每 64 或 128 个连续权重一个缩放系数）才让 4-bit 真正可行，代价是要存这些系数，
所以"4-bit"实际上是 4.25 到 4.5 个有效比特。

**误差落在哪里。** 舍入误差不是问题。问题是少数几个坐标大得离谱，为了罩住它们而
选的那一个缩放系数，把留给其他所有数值的精度都压扁了。

```python
def quantize_group(w, bits=4, group=128):     # w: list of floats, symmetric group-wise
    out = []
    for i in range(0, len(w), group):
        g = w[i:i + group]
        qmax = 2 ** (bits - 1) - 1
        s = max(abs(x) for x in g) / qmax or 1e-8       # one scale per group
        out += [s * max(-qmax - 1, min(qmax, round(x / s))) for x in g]  # quantize then dequantize
    return out                                  # returns the reconstructed weights
# smaller `group` -> less error, more scale overhead; group=128 is the common compromise
```

## 离群值问题，以及四个修法家族

大型 transformer 的激活分布里有少数几个通道，量级比其余通道大好几个数量级，而且
这些通道在功能上很重要，所以既不能为它们单独缩放，也不能丢掉。每一种像样的方法，
都是对这个事实给出的不同回答。

| 家族 | 思路 | 代表工作 |
|---|---|---|
| 把离群值留在高精度 | 把矩阵乘拆开：离群通道走 fp16，其余走 int8 | [LLM.int8()](https://arxiv.org/abs/2208.07339) |
| 把难度挪到权重上 | 逐通道缩放，把激活的离群值迁移到（更好处理的）权重张量里 | [SmoothQuant](https://arxiv.org/abs/2211.10438) |
| 保护重要的权重 | 舍入之前，先按激活量级找出显著的权重通道并缩放它们 | [AWQ](https://arxiv.org/abs/2306.00978) |
| 补偿自己造成的误差 | 逐层的二阶（Hessian 感知）舍入，把每次舍入误差推到还没量化的权重上 | [GPTQ](https://arxiv.org/abs/2210.17323) |
| 把离群值旋转掉 | 施加一个正交旋转，让任何坐标都不再是离群值，在旋转后的基底里量化 | [QuaRot](https://arxiv.org/abs/2404.00456)、[SpinQuant](https://arxiv.org/abs/2405.16406) |

最后一行是真正打开 4-bit *激活*和 KV 大门的那个，而不只是 4-bit 权重：旋转是可逆的，
又能折叠进相邻的矩阵，所以得到的是一个数学上等价、张量却恰好没有离群值的网络。
面试里只点一个近期进展的话，就点这个，并且加上实践里的注意事项：旋转必须融合进
模型里，运行时才不额外花钱。

## 每种格式是干什么用的

| 格式 | 典型用途 | 质量表现 | 提速机制 |
|---|---|---|---|
| int8 纯权重 | 内存卡住时的安全默认 | 配逐通道缩放几乎无损 | 权重字节减半；decode 带宽收益 |
| int4 分组纯权重（GPTQ、AWQ） | 让本来装不下的模型装下 | 平均损失小，集中在长尾；需要好的校准集 | 权重字节减到四分之一；小 batch 下 decode 收益很大 |
| fp8（e4m3）权重加激活 | 带 fp8 tensor core 的现代加速器 | 同样位宽下比 int8 更能容忍离群值 | 真正的算力提速，所以对 prefill 和高 batch 也有帮助 |
| 4-bit 权重加 4-bit 激活（基于旋转） | 在支持的 kernel 上激进地部署 | 现在能用，但仍是前沿；要分能力验证 | 算力和带宽 |
| nf4（QLoRA 风格） | 在冻结的量化底座上训练 adapter | 为正态分布的权重先验设计 | 省的是微调时的内存，不是服务格式 |
| 2-bit 及以下 | 研究，或者一开始就那样训练的三值模型 | 后训练 2-bit 退化剧烈 | 只有专门为此训练才可行（[BitNet b1.58](https://arxiv.org/abs/2402.17764)） |

BitNet 这条线值得搞清楚，恰恰因为它经常被引用错：1.58-bit 模型是在那个精度下
**训练**出来的；你没法把一个普通模型后训练量化到三值还保住它。

## 量化 KV cache

长上下文下，你在付钱的是 KV cache，不是权重。有两个性质让它和权重量化是不同的
问题：cache 是在服务时增量写入的（所以量化器必须便宜、能在线跑），而且 key 和
value 的分布不一样。文献里的实用配方是非对称的：key 按通道量化，value 按 token
量化，这样才尊重离群值真正所在的位置（[KIVI](https://arxiv.org/abs/2402.02750)）。

长上下文服务的操作顺序，按收益从大到小：

1. **架构层面的 KV 缩减**（GQA、MQA、MLA），前提是你能选模型。
2. **分页 KV**，省下来的内存才不会被碎片吃掉。
3. **KV 量化**到 8-bit，几乎免费；再到 4-bit，配分能力测试。
4. **淘汰或滑窗**放最后，因为它改变了模型能注意到什么。

四条的细节都在 [KV cache 那一章](../kv-cache/03-shrinking-the-cache.md)。

## PTQ、QAT，以及夹在中间的那个

**后训练量化（PTQ）** 只需要几百条样本的校准集，几个小时就能产出量化后的产物。
它是默认选项。

**量化感知训练（QAT）** 在训练的前向传播里模拟量化器，让权重学会对它鲁棒。在
激进的位宽下它能追回大部分质量差距，代价是一次训练。把它和全精度老师的蒸馏结合
起来，通常是 4-bit 及以下最强的选项。

**QLoRA 两者都不是。** 在冻结的 4-bit 底座上训练 LoRA adapter 是一种省内存的*微调*
技巧；底座在训练前就量化好并且一直保持量化，adapter 用更高精度训练。"我们用 QLoRA
把模型量化了拿去部署"是一个常见的混淆，值得避开。

## 什么时候用哪个

| 用什么 | 什么时候 | 而不是 |
|---|---|---|
| int8 纯权重，逐通道 | 模型差一点就装得下，想要最稳的收益 | 直接跳到 4-bit，把本来不必花的质量预算花掉 |
| int4 分组，GPTQ 或 AWQ | 内存卡住，而且小 batch 下的 decode 延迟很重要 | 非结构化剪枝，省了内存却没有提速 |
| fp8 权重加激活 | 加速器有 fp8 tensor core，卡住的是 prefill 或高 batch 吞吐 | 纯权重量化，FLOPs 一点没变 |
| 基于旋转的方法（QuaRot、SpinQuant） | 需要 4-bit 激活或 4-bit KV，不只是 4-bit 权重 | 认命说激活量化"做不了" |
| KV 量化 | 长上下文、大 batch，或两者都有 | KV 占大头时还在继续压权重 |
| QAT 加蒸馏 | 低于 4 比特，或者某个设备格式没有能保住质量的 PTQ 配方 | PTQ 加祈祷 |
| 按层混合精度 | 一次本来不错的量化之后，某一项能力退化了 | 把整个量化回滚 |

**出处。** 离群值分解这条线是 LLM.int8()（University of Washington 和 Meta AI，2022）；迁移和显著性这两条线是 SmoothQuant（MIT 和 NVIDIA，2022）和 AWQ（MIT，2023）；误差补偿这条线是 GPTQ（IST Austria 和 ETH Zurich，2022）；旋转这条线是 QuaRot（2024）和 SpinQuant（Meta，2024）；三值训练是 BitNet b1.58（Microsoft Research，2024）；KV 专属的非对称做法是 KIVI（2024）。

**工具。** PTQ 配方在 llm-compressor 和 AutoGPTQ / AutoAWQ 里都有，GGUF 加 llama.cpp 覆盖 CPU 和端侧路径；消费这些产物的服务运行时包括 vLLM、SGLang 和 TensorRT-LLM（NVIDIA），bitsandbytes 提供 QLoRA 用的 nf4 路径。通常决定选择的是格式支持而不是算法：选方法之前先查清楚你的运行时和加速器到底有哪些量化 kernel。

**实例。** 一个团队在一张加速器上服务交互式助手，先从 int8 逐通道纯权重量化开始，因为内存卡住而 int8 几乎无损；然后发现还是装不下，于是转到 int4 分组加 AWQ，校准集从真实线上流量里抽而不是通用网页文本，这样缩放系数才能匹配他们实际看到的代码和长文档形态。decode 延迟大致随权重字节数一起下降，对一个受带宽限制的阶段来说符合预期，而首 token 延迟几乎不动，所以他们没有为了 prefill 再继续压权重，而是在 kernel 支持的地方打开 fp8 计算。上下文长到 32K，所以他们在此之上把 KV cache 量化到 8-bit，同时保留分页注意力，让省下来的内存变成 batch 大小。验收测试抓到 JSON 工具调用合法性的退化，修法是把最后的投影层和注意力输出保持在更高精度，而不是放弃 int4。

## 实现上的坑

| 问题 | 症状 | 修法 |
|---|---|---|
| 校准集和线上流量不匹配 | 通用 prompt 上质量正常，代码、长文档或某个语言上退化 | 校准数据从真实流量抽，包括长上下文和工具调用的形态 |
| 所有层一刀切地量化 | 平均值看着正常，某一项能力崩了 | 敏感层（首尾几个 block、注意力输出投影、norm 和 embedding）保持更高精度 |
| 激活量化没有离群值策略 | loss 爆炸，或者输出语无伦次 | 用平滑、显著性感知的缩放或旋转；不要单纯往下降位宽 |
| 4-bit 配很大的分组 | 退化比预期大 | 缩小分组（128 到 64），并把缩放系数的开销算进真实的比特预算 |
| 在 benchmark 上而不是硬件上量收益 | 预测 2 倍，实测 1.1 倍 | 在目标硬件上跑 benchmark；决定速度的是 kernel，不是位宽 |
| 假设收益在高 batch 下也成立 | batch 1 很好，batch 64 纹丝不动 | 在生产 batch 下重新测；阶段会转向受算力限制 |
| 长上下文下 KV 留在 fp16 | 内存被 cache 占满；量化权重没换来多少 | 把 KV 量化并分页；考虑改用 GQA 或 MLA 模型 |

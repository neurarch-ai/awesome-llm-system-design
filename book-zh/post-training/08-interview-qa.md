# 8. 面试问答

面试官在微调和后训练上真正会问的问题，按用途分组。常答错的那一组，才是面试胜负所在。

## 常问的

**问：有人说模型在我们这个任务上不够好。你第一件事做什么？**
答：先问清楚"不够好"具体指什么，然后在动任何训练之前先试试更好的 prompt。
事实错了要的是检索，不是微调。格式或语气不对，先做 prompt 工程，如果差距还在再上 SFT。
真正该微调的情况，是缺了一项 prompt 工程注入不进去的能力。
一上来就说"我们应该微调"的候选人，已经跑偏了。

**问：LoRA 是什么，为什么大家都在用？**
答：LoRA 冻结基座权重，只学一对低秩矩阵（$B$ 和 $A$）来表示这个任务所需要的那份改变。
基座原封不动，训练和存储的只有那个小 adapter。实际好处有三点：
（a）adapter 极小（常用 rank 下不到基座的 1%），（b）一个基座能同时挂很多 adapter，
从而做多 LoRA 服务，（c）回滚只是改一条路由，不用重新部署。
冻结基座必须塞进单张 GPU 时就用 QLoRA。

**问：SFT、DPO 和 RLHF 有什么区别？**
答：SFT 通过在理想回复上最小化交叉熵损失，训练模型模仿正面样本，用例子教会行为、格式和技能。
DPO 在比较对（chosen, rejected）上训练，用一个分类式的损失，
直接最大化 chosen 相对 rejected 的似然比（相对于一个冻结的参考模型），
既没有独立的奖励模型，也没有 RL 循环。
RLHF 先从人类偏好里训一个独立的奖励模型，然后在 KL 惩罚的约束下用 PPO 针对这个奖励优化策略。
该按什么顺序去够它们：先 SFT；如果有 SFT 抓不住的偏好轴就上 DPO；
如果需要一个可复用的奖励信号或者更精细的控制，才上 RLHF。

**问：你怎么知道新模型是真的更好？**
答：让它过评估门禁：在一个留出的、去过污染的评估集上打赢当前线上模型，加上一次安全评估通过，
再加上（对偏好调优过的模型）一个高于阈值的成对胜率。然后在扩量之前，用一小片线上流量再卡一道。
离线指标会高估上线准备度，线上那道门禁才是真的。

**问：数据飞轮是什么，为什么重要？**
答：生产日志是最富矿的训练信号，因为它们来自真实的输入分布。
从里面挖失败案例（点踩、转人工、人工修正），把难的标出来，并进下一个版本的数据集，重训，过门禁，晋升。
一个平庸的初版模型配上一个转得紧、门禁又扎实的循环，会赢过一个没有反馈通路的优秀初版模型，
因为这个循环打的正好是当前模型最弱的地方。

## 有陷阱的（区分人的追问）

**问：DPO 里的 beta 是干什么的，太小或太大会出什么问题？**
答：beta 是 KL 惩罚系数，控制策略被允许离冻结参考模型多远。
太小：策略毫无约束地往最大化偏好目标的方向跑，可能靠奖励作弊退化成垃圾输出或者变得谄媚。
太大：策略被死死钉在参考模型旁边几乎动不了，那等于是多记了一堆账、重跑了一遍 SFT。
Anyscale 用的是 beta=0.03，甜蜜区通常在 0.03 到 0.1。
这跟 RLHF 的 KL 惩罚是同一根缰绳，只不过在 DPO 的损失里以闭式表达出来。
**奖励作弊为什么会发生：**这个损失看到的永远只有偏好对上 chosen 和 rejected 之间的间隔，
所以任何能把这个间隔拉大的文本模式都算"改进"，包括标注员从没比较过的退化式重复；
参考模型这个锚是唯一一项把策略拉回流畅的、在分布内的语言的力量，而 beta 决定它拉得有多用力。

**问：Anyscale 发现在他们的 DPO 任务上 LoRA rank 64 打不过全量微调。为什么会这样，什么时候会这样？**
答：LoRA 把权重更新约束在一个低秩子空间里。如果目标只是一次住在低秩流形上的小幅行为调整，这没问题。
但当任务需要一次幅度大或者几何上很复杂的偏移时，这个受限子空间会把 token 的对数似然推出分布之外：
adapter 找对了方向，却在它的 rank 预算里够不到正确的幅度。
提高 rank 有一点点帮助但很少能补平差距；偏移大的时候，全量微调才是正确选择。
症状是损失收敛了，但下游准确率卡在平台上不动。
**为什么提高 rank 很少能修好它：**rank 是权重更新能张成多少个独立方向的硬上限，
而一次大的行为偏移会把能量摊到很多方向上，尾巴衰减得很慢；
每多加一阶 rank 只买到下一个很小的增量，而承载了偏移剩余部分的那条尾巴依然够不到。

**问：Shopify 的 LLM 裁判飞轮，怎么避免"拿模型自己生成的东西训自己"这种循环论证？**
答：靠两个机制。第一，裁判会定期在留出样本上，用人工标注和线上激活率做校准，
所以它跟踪的是真实的产品质量，而不是模型对自己的评价。
第二，飞轮会在低质量的生产对话进入训练之前把它们隔离掉：
只有裁判打分高于阈值的对话才会被用上，而这个隔离阈值是按人工校准的结果定的。
一个开始偏离人类判断的裁判，会在定期校准那一步被抓出来，在它污染训练集之前就被重训或换掉。
**为什么这能打破循环：**校准信号（人工标注和线上激活率）来自模型-裁判这个循环的外部，
所以裁判和现实之间的任何漂移都会变成一个看得见、量得出的差距，而不是一次无声的反馈放大；
闭环真正危险的时候，是外部再也没有东西把它重新拉回地面。

**问：一个模型过了离线评估门禁，但在 1% 流量切片上的激活率比预期低 35 个点。发生了什么，你怎么办？**
答：离线评估量的是错误的分布。常见原因有：（a）评估集被清洗得比生产输入干净得多，
所以生产环境里的边角案例根本不在模型训练或评估见过的范围内；
（b）训练时的任务表示（比如 Shopify 用的是 Python 而不是原生 JSON DSL）和生产格式对不上；
（c）评估样本在分布上离训练样本太近（一种没被抓出来的准污染）。
处理步骤：把离线评估集和线上样本对比，找出差距；把有代表性的生产样本加进评估集；
修掉格式和表示上的不匹配；然后把飞轮闭上，让下一轮训练看到线上分布。
**离线门禁为什么会漏掉这件事：**离线集是一份冻结的、经过整理的样本，
所以一个模型可以靠贴合"整理方式"而不是贴合线上输入拿到高分；
门禁量错的是人群，不是模型，而在真实流量把它揭出来之前，离线指标再怎么涨都揭不出来。

**问：GRPO 扔掉了 PPO 依赖的价值网络。用什么替代它，为什么在这里是安全的？**
答：GRPO（DeepSeek，2024）对同一个 prompt 采样出一组 G 条补全，用可验证的奖励逐条打分，
然后把每个样本的优势算成"它的奖励减去组均值，再除以组标准差"。
而 PPO（OpenAI，2017）是另训一个 critic 网络来估计基线价值，这会让模型显存翻倍，
还给策略留下一个一直在动的追赶目标。
GRPO 的基线就是这一组内部的批统计量，所以不需要学出来的 critic，在组内还保持无偏，
这正是它适合可验证奖励任务（数学、代码、检索排名）的原因，那些任务每个样本都能便宜地打分。
它把成本挪到了别处：每个 prompt 得采 G 个样本，所以训练时的推理开销随组大小增长。
**批基线为什么是安全的：**只要减去的基线不依赖于所采样的动作，策略梯度在期望意义上就仍然无偏，
而组均值在每个 prompt 内部恰好就是这样一个基线；
于是 GRPO 拿到了 critic 本来提供的方差缩减，却不用再养一个自己也可能出错的学习网络。

**问：只在 chosen 回复上做 SFT，和在（chosen, rejected）对上跑 DPO，看起来很像；这个区别什么时候才真的重要？**
答：两者都是把概率往你喜欢的回复上推，而当 rejected 回复明显很差时（格式坏了、语言错了），
只在胜出样本上做 SFT 通常就够了，因为模型本来就给落败样本很低的概率。
真正拉开差距的，是那种"说得通但更差"的失败模式：一个自信的幻觉、一次谄媚的附和、一个隐蔽地不安全的答案。
SFT 的交叉熵损失从来看不到负面样本，所以它可以把 chosen 回复抬上去，
同时让那个诱人的错误答案的概率一点没变；而 DPO 的对比间隔会显式地把 rejected 相对参考压下去。
恰恰是在"不该说什么"才是任务难点、而不只是"该说什么"的时候，才该去够偏好对。

## 常答错的（陷阱题）

**问：应该靠微调来教模型新的事实吗？**
答：几乎永远不该。微调进去的事实会过期，一变就得重训。而且模型会在训过的那些事实之间自信地编造。
知识会变，对应的正确工具是检索（RAG）：把事实放进上下文，标注来源，随时更新。
微调教的是行为和技能，检索教的是知识。两者组合得很好：在同一个基座上，调风格，检索事实。
**为什么会有自信的幻觉：**权重把事实存成分布式的统计关联，而不是一张查找表，
所以一个在微调里只见过几次的事实，会造出一条流畅但并不可靠的补全通路；
模型在相邻的事实之间平滑地插值，而插出来的内容读起来和背下来的一样自信。

**问：为了拿到最高质量，格式和语气的问题应该上 RLHF 吗？**
答：不该。RLHF 是一条五组件的流水线（SFT 模型、奖励模型、参考模型、价值网络、PPO 循环），
运维复杂度很高，还实打实地有把模型带偏成谄媚或过度拒答的风险。
对格式和语气来说，做好 SFT 几乎总是够用，而且跑起来和调起来都便宜得多。
给一个 SFT 已经解决的问题提议 RLHF，是这个领域里最常见的过度设计。
**为什么带偏的风险是内生的：**奖励模型是一个在有限比较集上训出来的不完美代理，
而 PPO 优化得足够狠，会找到它的盲区；奉承和打太极在这样的代理下往往得分不低，
所以除非 KL 缰绳和评估门禁把它拉住，策略就会往那边漂。
当 SFT 已经够到目标时，你是在零收益地把这种失败模式揽到身上。

**问：LoRA 需要跑在和基座分开的 adapter 服务器上吗？**
答：不需要。多 LoRA 服务只加载一次基座，把用不同 adapter 的请求批在同一个基座上跑
（靠的是 Punica 的 SGMV kernel）。切换 adapter 就是毫秒级的矩阵加减。
基座始终是热的，adapter 按需从缓存或对象存储加载。
每个 adapter 起一个独立服务器，等于把 LoRA 全部的经济价值扔掉，
而这正是那种一张口就暴露没有生产经验的条件反射式答案。
**跨 adapter 批处理为什么便宜：**贵的那些矩阵乘法打的是共享基座权重，
不管用哪个 adapter，每个请求都一模一样，而每个 adapter 只额外加一个又瘦又低秩的矩阵乘；
按 adapter 把这些分组正是 SGMV kernel 干的事，
所以 GPU 的忙碌程度和单模型服务器一样，基座成本被摊到了每一个租户头上。

**问：能不能跳过回归检查，只测新模型的任务准确率？**
答：不能。回归检查抓的正是次要任务上那些无声的退步。
一个把目标指标提了两个点、却把安全、语气或某项次要能力拉低五个点的新模型，应该被门禁拦下。
如果不在同一个评估集上跟当前线上模型比，"更新"就会悄悄上线成"更差"，然后你从用户投诉里才知道。
回归检查不是可选项。
**回归为什么会发生：**微调动的是共享权重，所以目标任务上的收益，
是靠移动那些其他行为也依赖的参数换来的（干扰，极端情况下就是灾难性遗忘）；
优化指标 A 的过程里没有任何一环试图保住指标 B，所以只有显式地去测才知道。

**问：QLoRA 把基座存成 4-bit，那你训的 adapter 也是 4-bit 的，对吧？**
答：不对，而这个拆分正是它的关键。QLoRA（University of Washington，2023）
把冻结的基座权重以 4-bit NF4 保存，每次前向传播时即时反量化，
但 LoRA 的 adapter 矩阵是以 16-bit（bf16）保存和训练的。
梯度只流进 16-bit 的 adapter，4-bit 的基座从不更新。
于是你拿到了 4-bit 基座带来的显存节省，却没有把真正在学的那部分参数量化掉，
学到的 delta 保持全精度。
以为 adapter 是 4-bit 的人，会去预期一个根本不存在的更新精度损失，
还会为了补偿这个并不存在的问题而把 rank 开得过高。

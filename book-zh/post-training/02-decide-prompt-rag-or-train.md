# 2. 决策：prompt、RAG 还是训练

面试里要把这个顺序大声说出来，因为顺序本身就是信号。每一级都比它下面那一级更便宜、更快。
停在第一个能过质量线的那一级。

## 决策阶梯

**第 1 级：prompt 工程。**改写 system prompt、加 few-shot 示例、引入输出 schema、把复杂请求拆成步骤。
这一步免费、即时可迭代，而且是基线。如果从来没先调过 prompt，就无从知道微调到底有没有帮上忙。

什么时候管用：格式差距、语气差距、指令遵循失败，以及模型本来有这个能力、只是没被引导去用的任务。

什么时候不够用：基座模型确实不具备的技能；一段很长的 few-shot prompt，出于成本考虑想把它压缩掉；
一种必须在几百万次调用里都高度一致的行为。

**第 2 级：检索增强生成（RAG）。**把事实放进上下文，而不是放进权重。RAG 在文档改动的那一刻就更新了，
能引用来源，不需要跑训练，也不会像烤进权重的知识那样过期。决策规则是：
**RAG 教模型它不知道的东西，微调教模型该怎么表现。**

什么时候管用：差距在于知识（你们的文档、产品目录、客服工单），而且这些知识会随时间变化。

什么时候不够用：问题不在知识，而在行为、语气或格式。一个检索得很完美、写出来的风格却仍然不对的模型，
需要的是微调，不是更多检索。两者配合得很好：在同一个基座上，用微调管行为，用检索管知识。

**第 3 级：监督微调（SFT）。**把想要的输入和输出展示给模型，训练它产出这样的东西。
适合稳定的输出格式、领域特有的语气、某种推理模式，或者基座模型做得磕磕绊绊的结构化抽取技能。
也是把一段长 few-shot prompt 压进权重的办法，这样每个请求只需要付短 prompt 的成本。

什么时候管用：手上有几千条干净的标注样本，行为本身稳定（不是每周都在变），而且 prompt 工程之后还留着一个明显的差距。

什么时候不够用：需要从两个都说得通的答案里挑出正确的那个，或者要在安全轴上对齐模型，
或者要压制一种诱人但错误的风格，而单靠 SFT 没法可靠地排除它。

**第 4 级：偏好优化（DPO，direct preference optimization，或 RLHF，reinforcement learning from human feedback）。**
在比较数据上训练："对这个 prompt，这个回复比那个好。"它教模型在两个都可接受的答案之间*偏向*一个，
这是 SFT（只会模仿正例）表达不了的。细节见方法那一节。

什么时候管用：SFT 之后，某个你在意的质量轴（有用性、安全性、从两个合法答案里挑更好的）仍然没达标；
手上有比较数据，或者能生成出来。

什么时候不够用：SFT 已经把问题解决了。给一个格式加语气的问题提议上 RLHF，是过度设计，也是常见的面试陷阱。

## 要主动点破的陷阱

用微调来教事实，代价高、会过期，会在训练过的事实之间自信地产生幻觉，而且事实一变就得重做。
差距是知识，就去找检索；差距是行为，就去找微调。往哪个方向搞错都是常见且昂贵的错误，
把这一点明确说出来，是这道题里最清楚的信号之一。

## 什么时候用哪个

| 选择 | 时机 | 而不是 |
|---|---|---|
| prompt 工程 | 差距在格式、语气或指令遵循；零成本，即时迭代 | 在拿到基线之前，就上这张表里下面的任何一项 |
| RAG | 差距是随时间变化、且必须引用来源的知识 | 把会过期的事实微调进权重，更新还得重训 |
| SFT | 行为或技能差距；手上有几千条干净的标注样本 | 对一个关于风格而非知识的问题用 RAG |
| 偏好调优（DPO 或 RLHF） | SFT 抓不住的质量轴：安全、有用性、挑出更好的答案 | 当更好的样本已经能补上差距时，还继续用 SFT |
| 以上都先不做 | 问题描述太模糊，无法诊断 | 在基线还没测出来之前就决定跑训练 |

**每一级的工具。**prompt 工程除了模型 API 和一个用来测基线的评估 harness，什么都不需要。
RAG 由检索和编排栈来支撑，比如架在向量库上的 LlamaIndex、LangChain 和 Haystack。
SFT 和偏好调优都跑在 Hugging Face TRL 上（它的 SFTTrainer 和 DPOTrainer），
通常搭配 PEFT（参数高效微调，只训练一个小的附加模块而不是全部权重）来训 LoRA 或 QLoRA
（低秩 adapter 方法，方法那一节会定义）adapter，而 Axolotl 和 Unsloth 这类更上层的封装
让训练配置变成声明式的。当一次训练超出单张 GPU 时，由 DeepSpeed（Microsoft）承担分布式训练。

**出处。**RAG 由 Meta FAIR 提出（2020）。偏好调优这一级可追溯到 OpenAI 的 RLHF/InstructGPT（2022）
和 Stanford 的 DPO（2023），参数高效的 adapter 则来自 LoRA（Microsoft，2021）和 QLoRA
（University of Washington，2023）。

**一个完整的例子。**一个客服自动化团队发现助手的回答语气不对，而且不知道当前的退货政策。
他们从第 1 级开始，改写 system prompt，语气修好了，但政策的差距没补上，因为政策每个季度都变，
而且必须引用来源文档。这种知识差距正是 RAG 的用武之地，所以他们把政策页面建了索引，
而不是把日期烤进下一次修订就过期的权重里。当语气在几百万次调用中仍然漂移时，
他们在精选的对话记录上加了一小轮 SFT，让声音保持一致，在同一个基座上把调出来的行为和检索来的知识组合起来。
偏好调优他们暂时按下不做，因为 SFT 已经把差距补上了。

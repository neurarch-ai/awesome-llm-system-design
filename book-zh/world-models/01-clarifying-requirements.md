# 1. 澄清需求

"世界模型"这个词底下至少藏着四种不同的产品。面试的第一件事就是钉死到底是哪一种，
因为数据、架构，尤其是评估方式，在这几种之间完全不一样。

**候选人：** 您说的世界模型，是想要一个*预测未来*的模型，还是一个也要*执行动作*的模型？
纯预测器看预测准不准；世界动作模型看任务完成率。

**面试官：** 假设最终目标是控制。我们想让机器人完成一些没有专门训练过的操作任务。
世界模型是达成这个目标的手段。

**候选人：** 那北极星指标就是下游任务成功率，不是视频质量。再问两个问题。
第一，观测空间和动作空间是什么：第三人称视频，还是第一人称摄像头加本体感知？
输出是关节力矩还是末端执行器的位移增量？第二，在哪里评估：只在仿真里，
还是也上真实硬件？这两个答案基本决定了后面所有事情。

**面试官：** 输入是第一人称 RGB 加本体感知，输出是末端执行器的位移增量。
开发阶段在仿真里评估，但验收标准是在一个模型从没见过的新实验室里，真机任务成功。

**候选人：** 最后这条约束才是难点：零样本迁移（在一个全新的环境里工作，
不在那里做任何额外训练）到新的真实环境。这就把我们推向一条路：
先在大规模被动视频上预训练一个通用的动力学模型（让它广泛地学会物理规律），
再用少量带动作标注的机器人数据做适配，而不是在某一个实验室里从零训练一个策略
（策略就是从状态到动作的映射规则）。这也意味着评估必须把 sim-to-real 差距
（模型在真实硬件上比在仿真里差多少）明确地测出来，不能只报一个仿真器分数。

## 这些回答钉住了什么

| 澄清问题 | 如果答案是…… | 后果 |
|---|---|---|
| 预测还是执行？ | 执行（控制） | 成功率是指标；视频保真度只是代理指标 |
| 观测空间 | 像素还是低维状态 | 像素需要 tokenizer 或隐变量编码器；低维状态可以用紧凑的动力学模型 |
| 带动作标注的数据量 | 稀缺 | 在被动视频上预训练，用手头那点动作数据做适配 |
| 评估场景 | 仿真加真机 | 必须报 sim-to-real 差距，不能只给一个仿真器分数 |
| 开环还是闭环 | 闭环控制 | 短视野预测加重规划，胜过长视野的视频精度 |
| 机器人上的延迟预算 | 每步几十毫秒 | 规划算力（rollout 条数乘以视野长度；一条 rollout 就是往前推演出的一条想象轨迹）变成硬性设计约束 |

## 要避开的坑

经典的错误答案是把世界模型当视频生成器来优化：追 FVD（Frechet Video Distance）
和照片级真实感，展示一段漂亮的预测视频，然后就停了。一个模型可以生成华丽、
物理上合理的视频，但如果预测出的未来不能正确响应 agent 选择的动作，
它对控制来说照样没用。先钉住控制目标，后面每一节都从它出发。

## 要写下来的需求

- **功能性：** 给定当前观测和一段候选动作序列，把未来状态预测到足以选出一个好的下一步动作；
  闭环执行；泛化到没见过的物体、场景，以及（理想情况下）新的硬件。
- **非功能性：** 每步规划延迟要落在机器人的控制预算之内；训练数据预算以便宜的被动视频为主，
  外加一小份带动作标注的数据；评估在仿真里持续跑，在真实硬件上按里程碑跑；
  要报告 sim-to-real 差距。

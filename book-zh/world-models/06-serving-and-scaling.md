# 6. 服务与扩展

世界模型的服务分成两种截然不同的场景，把它们混为一谈就是设计错误。在线的时候，
模型跑在机器人身上，处在一个实时控制回路里，延迟预算是硬的。离线的时候，同一个模型
在数据中心里成批地跑，用来生成合成数据和评估策略，这时候重要的是吞吐，延迟无所谓。

## 在线：规划的延迟预算

控制时的开销主要来自规划器，而不是某一次前向。一个交叉熵方法的规划器，
大致要做

$$\text{model calls per step} \approx n \times \text{horizon} \times \text{iters}$$

所以一个规模不大的规划（200 个采样、horizon 为 5、3 轮细化迭代），机器人每走一步动作
就要跑大约 3000 次世界模型。如果控制回路是 10 Hz，这些全都得在 100 毫秒左右跑完。
有三个手段能让它可行：

- **廉价的状态表示。** 隐空间动力学模型和 JEPA 往前推演的是一个小向量，不是一整帧画面，
  所以实时控制基本被它们占着，而生成式视频模型主要用在离线。
- **批量 rollout。** `n` 条采样出来的动作序列彼此独立，那就在 GPU 上合成一次批量前向来算，
  别写 Python 循环。
- **缩短 horizon，多重规划几次。** 因为预测误差会累积（第 5 节），短 horizon 加上频繁重规划，
  既比长的开环规划准，也比它便宜。

## 离线：把世界模型当数据引擎和评估引擎

第二种场景在生产里往往价值更高。一个慢到没法拿来规划的生成式世界模型，成批地跑起来
依然非常有用：

- **生成合成数据。** 造出带动作标注的轨迹，以及那些在硬件上采集成本很高的罕见或危险场景，
  把策略训练的数据覆盖面撑开。NVIDIA Cosmos 就是明确冲着这个定位去的。
- **在仿真里评估策略。** 让候选策略对着世界模型（或者用它搭出来的仿真器）跑上几千次，
  在碰真实硬件之前先估出成功率，这正是把第 5 节里那条昂贵的真机轨道换成廉价仿真代理的办法。

这里扩展的目标是吞吐：GPU 上开很多并行环境（Isaac Lab 这类 GPU 并行仿真器能同时跑几千个环境）、
大 batch size，以及没有单次请求的延迟约束。

## 什么时候用哪种服务场景

| 场景 | 适用条件 | 工具 |
|---|---|---|
| 机器人本体规划（在线） | 闭环控制，每步有硬性延迟预算 | 隐空间动力学或 JEPA 模型，机器人 GPU 上的批量 CEM / MPC |
| 批量生成（离线） | 为策略训练造合成数据或补场景覆盖 | 生成式视频世界模型（Cosmos），GPU 并行仿真 |
| 批量策略评估（离线） | 在上硬件试验前廉价地给一堆策略打分 | GPU 并行仿真器（Isaac Lab），把世界模型当成环境 |

**工具。** 在线控制：DreamerV3 和 V-JEPA 2 的动作条件化模型，配一个批量的交叉熵方法规划器；
人形机器人上的 VLA 策略用 NVIDIA Isaac GR00T。离线生成与评估：NVIDIA Cosmos 世界基础模型，
以及并行跑几千个环境的 GPU 并行仿真器（NVIDIA Isaac Lab、dm_control、ManiSkill）。

**出处。** 在线控制的模型是 DreamerV3（DeepMind）和 V-JEPA 2（Meta，2025），
由一个交叉熵方法规划器（Rubinstein）驱动，外面套一层模型预测控制（经典控制理论）；
VLA 那条路线是 NVIDIA Isaac GR00T，离线生成器是 NVIDIA Cosmos。

## 瓶颈

| 瓶颈 | 症状 | 解法 |
|---|---|---|
| 规划器撑爆控制预算 | 机器人动作发抖或者慢半拍 | 减小 `n` 或 horizon，批量做 rollout，换更便宜的隐状态 |
| rollout 误差累积 | 规划看着挺好，horizon 一长就失败 | 缩短 horizon，更频繁地重规划，把 rollout 漂移加进评估 |
| sim-to-real 差距 | 仿真成功率高，真机成功率低 | 域随机化，更真实的接触物理，补更多真机适配数据 |
| 离线生成太慢 | 合成数据管线喂不饱策略训练 | 量化生成模型，横向扩容，缓存可复用的 rollout |

**细节。** 规划器预算那一行里的 n 和 horizon，是交叉熵方法规划器（Rubinstein）的两个开销乘数：
CEM 采样 n 条长度为 H 的候选动作序列，每条都过一遍世界模型，留下打分最高的那一小撮精英，
重新拟合采样分布，如此迭代几轮，所以每步开销随 n 乘 H 乘迭代次数增长；
模型预测控制（经典控制理论）随后只执行第一个动作，下一步重新规划。
rollout 误差累积那一行，解释了为什么不能简单地把 horizon 拉长：每一个预测步都以上一步的预测为条件，
于是每步的小误差会在整个 horizon 上累积起来，而更频繁地重规划（等效 horizon 更短，
且每一步都拿到一个新的真实观测）比一个更长的开环规划更能把漂移控制住。

# 2. 搭出 benchmark 的骨架

## 一个 benchmark 分数到底是什么

一个 benchmark 分数背后是三项承诺。把它们一一点名，是让自己听起来像真跑过评估、而不是只读过评估的最快方法。

- **一个构念（construct）。** 你声称在测量的那种潜在能力（"它会不会做竞赛数学"、"它能不能解决一个真实的 GitHub issue"）。构念从来不能被直接观测。
- **一个题目总体。** 你抽出来当构念代理的那组有限的任务。分数是一个样本统计量，所以它带抽样误差，而且这个总体未必能代表构念（竞赛数学不等于工程数学）。
- **一套协议。** 每道题怎么变成 prompt，模型怎么跑，输出怎么变成一个数。同一批题目、同一个模型，换一套协议分数就不同，差 10 分以上是家常便饭。

大多数关于 benchmark 的争论，其实都是在争这三者之一，只是双方嘴上说的都是那个数字。"这个 benchmark 是不是饱和了"是题目总体的争论；"我的 MMLU 为什么比你低 8 分"几乎总是协议的争论；"SWE-bench 能不能预测工程生产力"是构念的争论。

## 模型级评估和系统级评估

| 维度 | Benchmark 评估（本章） | 系统评估（[评估一章](../evaluation/)） |
|---|---|---|
| 被测对象 | 一个模型，钉在一个固定版本上 | 一个候选方案：prompt 加模型加配置加检索加工具 |
| 题目来源 | 公开或内部的 benchmark 套件，固定不变 | 从自己的流量里采样出来的 golden set |
| 决定什么 | 在哪个模型上构建；一次训练 run 有没有改善 | 这个改动今天能不能上线 |
| 可比对象 | 别人公开发表的数字、其他 checkpoint | 自己的生产 baseline |
| 主要风险 | 污染、协议漂移、构念不匹配 | judge 校准失准、切片回归、golden set 过时 |
| 节奏 | 每个 checkpoint、每个候选模型、每个季度 | 每次 commit、每次改 prompt |

两者共用机器（harness、judge、统计），回答的是不同的问题。代价最高的失误是把一个用在另一个的位置上：用 MMLU 给产品改动做门禁，或者拿一个只覆盖一种 prompt 的 200 行产品 golden set 去选底座模型。

## 能力组合

挑 benchmark 要像挑测试套件一样：看它坏掉的时候能抓住什么，而不是看它有多出名。到 2026 年，2021 到 2023 年间的那批多选题套件（MMLU、HellaSwag、GSM8K、HumanEval）在前沿模型上已经饱和，也就是说它们剩下的信号主要是标注噪声，真正有意义的家族是下面这些。

| 能力 | Benchmark 家族 | 真正测的是什么 | 怎么坏 |
|---|---|---|---|
| 知识与推理 | GPQA Diamond、MMLU-Pro、Humanity's Last Exam | 专家级问题上的回忆加多步推断 | 题目数太少（GPQA Diamond 只有 198 题）导致误差棒很宽；公开镜像带来的污染 |
| 数学 | AIME 风格的竞赛题集、FrontierMath | 格式约束下的符号化多步推导 | 30 题的集合里一道题就超过 3 分；答案等价性解析出错 |
| 代码（单测验证） | SWE-bench Verified、LiveCodeBench、HumanEval 风格的 pass@k | 产出能通过测试的补丁或函数 | 弱测试套件放过错误补丁；harness 和容器漂移；老题目上的污染 |
| Agent 与工具调用 | tau-bench 和 tau2-bench、BFCL、GAIA、终端和 computer-use 套件 | 在策略约束下带状态的多步工具调用 | 什么都不做被算成成功；部分得分掩盖失败；环境不稳定 |
| 长上下文 | RULER、HELMET、多轮指代消解检索集 | 跨长输入的检索和聚合，而不只是找一根针 | 大海捞针接近满分，却迁移不到真实任务 |
| 指令遵循 | IFEval 风格的可验证约束集 | 服从显式的输出约束 | 用侧重格式的后训练很容易过拟合 |
| 多模态 | MMMU-Pro 及其后继 | 跨模态推理，而不是配字幕 | 纯文本捷径就能解掉很多题 |
| 安全与拒答 | 越狱和策略套件、对抗性红队集 | 对抗压力下的行为 | 同一套集合测不出过度拒答；需要配一套良性题 |
| 有经济价值的工作 | GDPval 风格的专家任务集、METR 时间跨度套件 | 长而真实的任务到底能不能做完 | 昂贵；n 小；需要人类基线 |

两条选择规则干了大部分活。**优先选还有提升空间的 benchmark**：所有候选都在 90% 以上的 benchmark 没法给它们排序，因为剩下的差距落在标注错误率之内。还有，**永远至少包含一个私有的内部 benchmark**，从自己的工作负载里造出来，因为它是唯一能证明从没被训练过的集合，也是唯一构念和产品对得上的集合。

## 饱和、提升空间与区分度

两个模型在一个饱和的 benchmark 上分别拿 94.1 和 94.6，它们不是差 0.5，而是在标注噪声之内打平。一个 benchmark 对*排序*有没有用，取决于题目难度相对于被测模型的分布：所有候选都能解的题和所有候选都解不了的题，都只贡献方差，不贡献信息。这和项目反应理论形式化的直觉是同一个，也是前沿实验室不断退役 benchmark、而不是永远报下去的原因。

采用一个 benchmark 之前的实用测试：拿两个你已经知道有差别的模型跑一遍，看这个 benchmark 能不能把它们分开、并且分开的幅度超过它自己的置信区间。分不开已知的一对，就更分不开未知的一对。

## 构念效度：分数是不是你打算用它做的那个意思

分数可以测得完美无缺，却依然支撑不了那个决策。

- **多选题捷径。** 很多多选题不看题干、只看选项的模式就能答到高于随机水平，所以这种格式测的是在给定选项里做区分的能力，而不是产出答案的能力。近期工作发现，自由生成加参考答案匹配对同一构念的测量更好（[Answer Matching Outperforms Multiple Choice for Language Model Evaluation](https://arxiv.org/abs/2507.02856)）。
- **题目效度。** Benchmark 里有坏题。对数千道 MMLU 题目的人工重新标注发现各学科都有个位数百分比的错误率（解析错误、多个正确选项、没有正确选项、缺上下文），发布为 MMLU-Redux（[Are We Done with MMLU?](https://arxiv.org/abs/2406.04127)）；对经过对抗过滤的常识题集做效度审计，发现相当大一部分题目有语法或语义问题（[What the HellaSwag? On the Validity of Common-Sense Reasoning Benchmarks](https://arxiv.org/abs/2504.07825)）。标注错误封住了可达到的最高分，并且恰好在模型拉开差距的地方加噪声。
- **Agent 高估。** 结果验证太弱，agent 就能不解决任务也"通过"。一项系统审计发现，SWE-bench-Verified 风格的设置会高估能力，因为测试套件弱到拒绝不了错误补丁；tau-bench 里宽松的判定标准会把什么都不做算成成功（[Establishing Best Practices for Building Rigorous Agentic Benchmarks](https://arxiv.org/abs/2507.02825)）。
- **总体不匹配。** 竞赛数学预测的是竞赛数学。如果产品是技术文档上的检索，数学分数就是代理的代理。

## 对比：五种都被叫做"那个 benchmark"的工具

| 工具 | 给你什么 | 给不了什么 | 成本 |
|---|---|---|---|
| 静态公开 benchmark（GPQA、MMLU-Pro） | 和已发表数字的可比性；便宜、可重复 | 免于污染；构念和你的任务匹配 | 低 |
| Live 或按时间闸门的 benchmark（LiveBench、LiveCodeBench） | 题目在模型截止日期之后发布，污染在构造上就是有界的 | 跨时间的稳定可比性；题库在你脚下不停变 | 低到中 |
| 私有内部 benchmark | 构念匹配，加一个能证明的无泄漏故事 | 外部可比性；一个可引用的公开数字 | 中（标注） |
| 人类偏好 arena | 真实 prompt 上大规模聚合的人类口味 | 任务级的正确性；对风格和 best-of-N 提交效应免疫 | 中（流量） |
| 人类增益或专家试验 | 模型是否改变了真实工作的结果 | 吞吐；没法每个 checkpoint 都跑一次 | 高 |

完整的回答要跑一个组合：两三个有提升空间的公开 benchmark 负责外部可比性，一个 live benchmark 当污染检查，一个私有内部 benchmark 作为正式的决策依据。

## 流水线的输入和输出

**输入：** 一组候选，每个候选是（模型标识、版本或快照、推理服务栈、解码配置、测试时计算预算）。同一个模型的两种预算设置是两个候选，不是一个。

**每次运行的输入：** 一个钉住版本的 benchmark，在 benchmark 有题目发布日期的情况下包含发布日期。

**输出：** 对每个（候选、benchmark、切片）：一个点估计、一个区间、一个采样数、一个以 token 和美元计的成本、一个协议哈希。再加上对每一组你被要求做的两两比较的裁定：更好、更差，或者在这个样本量下分不出来。"分不出来"是一个正当的、而且经常是正确的答案，愿意给出这个答案是资深的信号。
